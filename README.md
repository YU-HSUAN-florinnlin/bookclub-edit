# bookclub-edit

**版本 0.1.0（測試版）**：流程八步裡，第 1 步的分析全部完成，第 2、4 步有部分介面，還不能產出處理過的影片。版本號 0.x 代表介面與檔案格式還可能改變。

讀書會 Zoom 錄影的隱私處理工具：把學員的聲音跟姓名去識別化，老師原音保留。**在自己電腦上跑，影片跟個資都留在本機**，不上傳、不進這個公開倉庫。

## 1. 這是什麼

一句話：半自動工具，把讀書會影片裡的學員聲音換成 AI 合成聲線、學員姓名換成代號，老師的部分照樣保留。

目前完成到哪一步：

- **流程第 1 步「轉文字與分析」已經做完並實跑驗證過**：轉文字 → 認出老師是誰 → 找出誰跟誰重疊講話 → 自動挑老師參考音 → 找出學員姓名候選。這幾步可以用 `bookclub run analyze` 一次跑完（見下面「怎麼用」）。
- 本機網頁（`bookclub serve`）目前有三頁真的能用：
  - 第 1 步進度頁（轉文字與分析的五個子步驟完成狀態、耗時）
  - 第 2 步「聲音分群與參考音」：確認老師的參考音、修逐字稿、選定
  - 第 4 步「標記覆核」：逐筆聽找到的姓名候選，勾選判斷（不是名字／是地名／切點削到旁邊的字）

**還沒做的部分**：學員逐字稿校對（第 3 步）、AI 聲音生成與時間格處理（第 5 步）、成品逐筆覆核（第 6 步）、整片檢查與剪輯組裝匯出（第 7 步）。網頁上對應的步驟目前只會看到「這一步還沒做」的說明，`bookclub export`／`bookclub bench` 指令也是同樣狀態。

## 2. 整個流程要做哪些事

一支影片從原始錄影到可以發布的成品，要走過下面八步。「誰做」欄位的「電腦」表示按一個指令或按鈕之後自動跑完，不用顧；「人」表示要有人聽、看、判斷。

| 步驟 | 誰做 | 要做的事 | 這一版的狀態 |
| --- | --- | --- | --- |
| 0. 一次性設定 | 人 | 每一期讀書會建一次：名冊（本名、聽錯的寫法、英文代號、聲線、性別）、匿名聲線、名字排除清單 | 檔案格式已定（`profile.example/`），**沒有介面**，用文字編輯器改 CSV |
| 1. 轉文字與分析 | 電腦 | 抽出聲音 → 轉文字 → 認出老師 → 找出聲音重疊 → 挑老師參考音 → 找出姓名候選 | **已完成**，`bookclub run analyze` 一個指令跑完，網頁上看得到進度 |
| 2. 聲音分群與參考音 | 人 | 指認每個聲音編號是誰；聽老師參考音，有雜音、笑聲或別人的聲音就換一段，沒問題就修逐字稿、存檔 | **參考音確認已完成**（網頁第 2 步）；聲音編號指認的介面還沒做 |
| 3. 學員逐字稿校對 | 人 | 最花時間的一步。學員說的每句話逐句聽過改對——成品裡的學員聲音是照這份文字重念的，文字錯一個字就念錯一個字。名字與敏感詞在這裡換成代號 | **還沒做** |
| 4. 標記覆核 | 人 | 三類逐筆決定：老師提到名字（只換名字／整句換掉／直接消音）、聲音重疊（哪一邊保留）、要刪除的段落 | **姓名那一類已完成**（網頁第 4 步：逐字稿標色、原音與消音版試聽、勾選即時存檔）；重疊與刪除段落還沒做 |
| 5. AI 執行 | 電腦 | 用老師的 AI 聲音重念指定句子、學員整段換成匿名聲線，放回原本的時間；最後一次套用刪除與停格 | **還沒做**（聲音生成的做法與參數已經驗證過，尚未寫進工具） |
| 6. 成品逐筆覆核 | 人 | 每一筆聽「處理前／處理後」，不滿意退回重做 | **還沒做** |
| 7. 整片檢查與輸出 | 人 | 用 1.25–1.5 倍速看完整支，發現問題就地建一筆修補項目，只局部重做；確認後輸出 | **還沒做** |

另外，畫面的隱私處理（多人畫面模糊、Zoom 姓名標籤遮蔽）與片頭片尾，由剪輯軟體另外處理，不在這個工具的範圍內。

### 這一版能做到什麼

可以做完第 1 步的全部分析，拿到：整支的逐字稿、每一句是誰說的、聲音重疊清單、老師的參考音候選、學員姓名候選；並在本機網頁上確認參考音、逐筆覆核姓名候選。**還不能產出處理過的影片**——生成聲音與剪輯組裝（第 5、7 步）還沒開發。

## 3. 準備什麼

- **影片檔**：讀書會的錄影檔（Zoom 錄影通常是 .mp4），放在自己電腦上，路徑記下來就好，不用搬進這個倉庫資料夾。
- **Groq API 金鑰**（語音轉文字用，免費額度通常夠用）：
  1. 到 [console.groq.com](https://console.groq.com) 註冊、申請一把金鑰
  2. 設定環境變數（**不要把金鑰寫進任何檔案、也不要貼給 AI**）：
     ```bash
     export GROQ_API_KEY=你的金鑰
     ```
     macOS 預設殼層是 zsh，這行要加進 `~/.zshrc`；WSL2 的 Ubuntu 預設是 bash，加進 `~/.bashrc`，依實際使用的殼層調整。加完開一個新的終端機視窗才會生效。
- **硬碟空間**：第一次安裝建議至少留 15GB 可用空間（AI 模型約 7GB、Python 套件約 3GB，其餘是緩衝），寬鬆一點抓 30GB 以上比較保險。
- **名冊與敏感詞 CSV**：範例在 [`profile.example/`](profile.example/)，複製一份到自己的資料夾改內容（`install.sh` 會自動複製，見下）。
  - `名冊.csv` 欄位：`中文名`（學員本名）、`其他寫法`（同音字／暱稱，多個用「、」分隔）、`英文代號`（比對到之後要換成的代號）、`聲線`、`性別`
  - `敏感詞.csv` 欄位：`原詞`（要擋掉的詞，例如公司名、地名）、`替代詞`（換成什麼）
  - 這兩份檔案含真實姓名，不要提交進任何 git 倉庫，放在 `~/讀書會剪輯資料/`（見下面「產出在哪」）就不會被這個公開倉庫的 git 追蹤到。

## 4. 安裝

```bash
cd ~/Downloads/bookclub-edit    # 或你 clone 下來的位置
bash install.sh
```

`install.sh` 會依序做：檢查系統與空間 → 裝 Homebrew 套件（ffmpeg、uv）→ 建立 Python 3.11 虛擬環境（`.venv/`）→ 裝 Python 套件與 `bookclub` 指令 → 抓聲音生成引擎 CosyVoice 原始碼 → 下載三個 AI 模型 → 建立 `~/讀書會剪輯資料/` 資料夾（並複製 `profile.example/` 的範例檔進去）→ 建 Claude Code 的 skill 捷徑 → 跑一次環境健檢。**可以重複執行**：已經做過的步驟會自動跳過，不會重複下載，也不會刪掉已經調整過的設定。第一次安裝依網路速度可能要半小時以上，大部分時間花在下載模型。

**WSL2 注意事項**：這支安裝腳本目前只在 macOS（Apple Silicon）測過，**WSL2 尚未驗證**。腳本裡用了 `brew`、`sw_vers`、`sysctl` 這幾個 macOS 專屬指令，在 WSL2 的 Ubuntu 上大概率會卡住或報錯。遇到問題請把完整的錯誤訊息交給 Claude Code 排錯，Claude Code 應該能幫忙改成 Linux 對應的做法（例如系統套件改用 `apt`），**跑完之後麻煩把結果（順利或卡在哪、怎麼解的）回報**，方便之後把 WSL2 支援直接補進安裝腳本。

安裝最後會自動跑一次環境健檢（`bookclub doctor`），告訴你有沒有裝好、還缺什麼。另外「分辨誰在說話」用的 pyannote 模型是受限模型，要先到 Hugging Face 個別同意條款才能下載，`bookclub doctor` 沒過的話畫面上會有清楚的修法說明。

## 5. 怎麼用

以下範例路徑請換成自己實際的檔案位置。指令都用虛擬環境裡的 `bookclub`：`.venv/bin/bookclub`。

**環境健檢**：檢查有沒有裝好、模型在不在、金鑰有沒有設定。

```bash
.venv/bin/bookclub doctor
```

**流程第 1 步一次跑完**：轉文字 → 認老師 → 找重疊 → 挑參考音 → 找姓名，結果都寫進工作區資料夾。

```bash
.venv/bin/bookclub run analyze ~/讀書會剪輯資料/影片/第1堂.mp4 ~/讀書會剪輯資料/工作區/第1堂 --roster ~/讀書會剪輯資料/名冊.csv --sensitive ~/讀書會剪輯資料/敏感詞.csv
```

**單獨挑老師參考音**（`run analyze` 已經包含這步，這是要單獨重跑或測試時用）：

```bash
.venv/bin/bookclub ref pick ~/讀書會剪輯資料/影片/第1堂.mp4 ~/讀書會剪輯資料/工作區/第1堂
```

**選定某一個參考音候選**，存成正式的 `ref.wav`／`ref.txt`（`<名次>` 是 `ref pick` 推薦清單裡的第幾名，逐字稿先聽過修正好存成檔案再帶進去）：

```bash
.venv/bin/bookclub ref use ~/讀書會剪輯資料/工作區/第1堂 1 --text-file 修正後逐字稿.txt
```

**開本機網頁**（目前第 1、2、4 步可以互動操作，其餘步驟顯示「還沒做」）：

```bash
.venv/bin/bookclub serve ~/讀書會剪輯資料/工作區/第1堂
```

網址預設是 <http://localhost:8766>，會自動開瀏覽器（加 `--no-open` 不自動開）。也可以雙擊「啟動.command」自動挑最近修改過的工作區——但這是 macOS 的雙擊啟動檔，WSL2 沒有對應的雙擊行為，直接用上面的 `bookclub serve` 指令即可。

## 6. 產出在哪

每支影片對應一個工作區資料夾（例如 `~/讀書會剪輯資料/工作區/第1堂/`），檔案結構與每個欄位的說明見 [`docs/工作區格式.md`](docs/工作區格式.md)。

工作區放在 `~/讀書會剪輯資料/` 底下，不在這個 git 倉庫的資料夾路徑內，正常操作不會被這個公開倉庫的 git 追蹤到。但如果自己手動搬動檔案，以下這幾個**含學員內容，不要外流、不要進 git**：

- `transcript/`（含 Groq 轉出來的逐字稿原文）
- `說話者判斷.json`
- `名字候選.json`、`名字候選/`（含逐句逐字稿與姓名候選的試聽片段）
- `名字覆核.html`（覆核用的靜態網頁，含整句逐字稿）
- `名字覆核決定.json`
- `名冊.csv`、`敏感詞.csv`、`名字排除清單.csv`

終端機輸出跟 `報告.md`／`分析結果.json` 只放統計數字與耗時，不含逐字稿或學員說的內容，這兩份可以放心回報、討論。

## 7. 速度參考

第一堂實測（影片 98 分鐘，MacBook Air M1，只用處理器沒有用顯示卡）：

| 步驟 | 耗時 |
| --- | --- |
| 完整分析（`run analyze` 全部五步） | 7.9 分鐘 |
| 轉文字 | 約 100 秒 |
| 認老師 | 約 95 秒 |
| 找重疊 | 約 450 秒 |
| 挑參考音 | 約 22 秒 |
| 找姓名 | 約 5 秒 |

CosyVoice 生成聲音（第 5 步，還沒做）：每生成 1 秒的聲音，實測約需要 15–30 秒運算。

以上是 macOS Apple Silicon、純 CPU 的數字，WSL2 或不同硬體（尤其有沒有可用的顯示卡）耗時會不一樣，目前沒有 WSL2 的實測數字。

## 8. 隱私與授權

- **影片、名冊、逐字稿都不進這個倉庫**：這些檔案根本不在倉庫資料夾路徑下，統一放在 `~/讀書會剪輯資料/`（見上面「產出在哪」）。
- **雲端只有一件事**：轉文字這一步會把音訊片段送到 Groq 做語音辨識。其餘步驟（分辨誰在說話、找重疊、找姓名候選、之後的聲音生成）都在本機跑，不上傳。
- **模型授權**：聲音生成引擎 CosyVoice3 是 Apache-2.0 授權；分辨誰在說話用的 pyannote 可商用；另一個原本評估過的聲音生成方案 F5-TTS 因為授權不可商用，所以沒有採用。
- **倉庫本身**：這個程式碼倉庫用 [MIT License](LICENSE)。

## 9. 回報與聯絡

工具跑不動或結果怪怪的時候：

1. 先跑 `.venv/bin/bookclub doctor`，把**完整輸出**貼給 Claude Code。
2. Claude Code 會照輸出裡每一項的「修法」協助排除；WSL2 安裝過程的問題也先交給 Claude Code 排錯（見上面「WSL2 注意事項」）。
3. 還是不行的話，回報時請附上：
   - 錯誤訊息全文（不要只描述「壞掉了」，截圖或整段複製貼上）
   - 卡在哪一步（`doctor`／`run analyze`／`ref pick`／`serve` 的哪個階段，或網頁上哪一頁）
   - 大概跑了多久才出錯
   - 如果方便，加跑 `.venv/bin/bookclub doctor --smoke`（實際跑三個模型各處理一小段測試音檔），把輸出一起附上，裡面有更詳細的錯誤訊息
4. 把以上資訊回報給宇軒，一起討論下一步。
