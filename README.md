# bookclub-edit

**版本 0.2.0b1（測試版 beta1）**：流程六步（0～5）都有網頁可以操作：第 0 步初始化設定（設定包匯出／匯入）、第 1 步影片分析、第 2 步確認老師參考音、第 3 步覆核工作台、第 4 步 AI 執行（老師名字、學員重念、組裝成品影片）、第 5 步成品檢查。**還沒有整支影片從頭到尾跑過一輪**；畫面處理（學員的臉、Zoom 姓名標籤）還沒做。2026-09-29 已在 Windows 11＋WSL2 實測安裝與第 1 步（見「速度參考」）。版本號 0.x 代表介面與檔案格式還可能改變。

讀書會 Zoom 錄影的隱私處理工具：把學員的聲音跟姓名去識別化，老師原音保留。**在自己電腦上跑，影片跟個資都留在本機**，不上傳、不進這個公開倉庫。

## 1. 這是什麼

一句話：半自動工具，把讀書會影片裡的學員聲音換成 AI 合成聲線、學員姓名換成代號，老師的部分照樣保留。

目前完成到哪一步：

- **流程第 1 步「影片分析」已經做完並實跑驗證過**：轉文字 → 段落分析（Claude 看文字）、建議刪除段落（另一個 Claude 呼叫）與認老師（聲紋）同時跑 → 冥想引導、導讀整段算老師 → 找出誰跟誰重疊講話 → 自動挑老師參考音 → 找出學員姓名候選 → 學員段落整段認人。可以用 `bookclub run analyze` 一次跑完（見下面「怎麼用」）。
- 本機網頁（`bookclub serve`）目前這幾頁真的能用：
  - 總覽：選影片（按「開始分析」才在影片旁邊建這支影片的工作資料夾）、切換已有的專案
  - 第 0 步「初始化設定」：看共用設定、匯出／匯入設定包給夥伴
  - 第 1 步進度頁（各子步驟完成狀態、耗時）
  - 第 2 步「挑選老師參考聲音片段」：確認老師的參考音、修逐字稿、選定
  - 第 3 步「覆核工作台」（測試版）：先做開始前 4 件事，再邊看影片邊逐筆按「通過」（每一筆都已經有建議）；漏抓的用「＋新增修改」補（時間自動對齊）；匯出覆核結果交給夥伴
  - 第 4 步「AI 執行」（cloud 分支，測試版）：按「開始執行」依序跑老師名字 → 學員重念 → 組裝，做過的跳過
  - 第 5 步「成品檢查」（cloud 分支，測試版）：逐筆聽處理前後、整片看完 100%，有問題退回 AI 重做；全部通過才能輸出
  - 左側步驟列每一步標「AI」或「人工」，可以收合（記得上次的狀態）

流程（09-29 改成 0～5：原本第 5 步逐筆覆核、第 6 步整片檢查合成第 5 步「成品檢查」）：

| 步驟 | 誰做 | 內容 |
| --- | --- | --- |
| 0　初始化設定 | 人工（跨專案共用，做一次） | 名冊、敏感詞、名字排除清單、發音對照表、匿名聲線；可以匯出設定包給夥伴 |
| 1　影片分析 | AI | 轉文字、段落分析、認老師、找重疊、挑參考音、找名字、學員認人 |

| 3　覆核工作台 | 人工 | 開始前 4 件事（建議刪除段落、學員是誰、名冊上沒有的名字、誰保留原聲），再邊看影片邊逐筆通過；漏抓的用「＋新增修改」補 |

## 2. 這一版能做到什麼

第 1 步全部分析（逐字稿、每一句是誰說的、聲音重疊、老師參考音候選、姓名候選、建議刪除段落）；網頁上確認參考音、在覆核工作台逐筆決定怎麼處理；第 4 步生成老師名字與學員重念、組出處理過的影片（刪除、停格、局部消音）；第 5 步逐筆與整片檢查後輸出成品。**還不能處理畫面**（學員的臉、Zoom 姓名標籤）。

## 3. 準備什麼

第一次安裝前，照順序準備好這幾樣（打 ✱ 的是 WSL2 才要做的）：

| # | 要準備的 | 做什麼用 | 怎麼準備 |
| --- | --- | --- | --- |
| 1 | 硬碟空間 | 模型、套件、工作區 | 至少 15GB（模型約 7GB、套件約 3GB；WSL2 用只用處理器的 torch）；每支 2 小時影片的工作區另外抓 5–10GB |
| 2 | ✱ WSL2 記憶體上限 | 找重疊、組裝整支影片 | WSL2 預設只能用主機一半的記憶體。Windows 使用者資料夾建 `.wslconfig`，寫 `[wsl2]`、`memory=24GB`、`swap=16GB`，存檔後在 PowerShell 跑 `wsl --shutdown` 再開 |
| 3 | Groq API 金鑰 | 語音轉文字（免費額度通常夠） | 到 [console.groq.com](https://console.groq.com) 申請。把 `export GROQ_API_KEY=你的金鑰` 加進：**macOS → `~/.zshrc`**；**WSL2 → `~/.profile`**（不要放 `~/.bashrc`：Ubuntu 的 `.bashrc` 在非互動模式會提早結束，工具讀不到）。加完開新的終端機視窗。**金鑰不要寫進其他檔案、也不要貼給 AI** |
| 4 | Hugging Face 帳號與同意條款 | 分辨誰在說話（pyannote 是要先同意條款的模型） | ① 註冊／登入 [huggingface.co](https://huggingface.co) ② 打開 [pyannote/segmentation-3.0](https://huggingface.co/pyannote/segmentation-3.0) 與 [pyannote/speaker-diarization-3.1](https://huggingface.co/pyannote/speaker-diarization-3.1) 各按一次同意 ③ Settings → Access Tokens 建一把 **Read** 金鑰。登入指令在安裝完之後跑（見下一節） |
| 5 | Claude Code（登入過） | 段落分析、建議刪除段落、人名清單（第 1 步） | macOS 裝好 Claude Code 即可。**✱ WSL2 要在 WSL2 裡面另外裝一份**（Windows 那份 WSL2 用不到）：`curl -fsSL https://claude.ai/install.sh \| bash`，裝完執行 `claude` 登入一次。沒裝的話第 1 步會跳過段落分析，第 3 步沒有學員段落可以覆核 |
| 6 | 設定包（向宇軒拿） | 名冊、敏感詞、名字排除清單、發音對照表、**匿名聲線**（學員重念用的男聲、女聲） | 安裝完用 `bookclub profile import 設定包.zip` 匯入（見「怎麼用」第 0 步）。沒有設定包時，安裝會放範例檔，名冊要自己填、匿名聲線要另外準備 |
| 7 | 影片檔 | 讀書會的 Zoom 錄影（.mp4） | **✱ WSL2 先把影片複製到 WSL2 自己的資料夾**（例如 `~/影片/`），不要直接讀 `/mnt/c/...`：跨系統讀寫慢很多，工作區也會建在影片旁邊 |

名冊欄位：`中文名`（學員本名）、`其他寫法`（同音字、暱稱、轉文字常聽錯的寫法，多個用「、」分隔）、`性別`（決定用男聲或女聲重念）。**英文代號不寫在名冊**：每一集在第 3 步選（同一集同一人同一個代號就好）。敏感詞欄位：`原詞`、`替代詞`。這幾份含真實姓名，放在 `~/讀書會剪輯資料/`，不要提交進任何 git 倉庫。

## 4. 安裝

### 先檢查電腦裡已經有什麼

安裝前先跑這一行，它只檢查、不裝任何東西：

```bash
bash install.sh --check-only
```

畫面會列出系統工具（ffmpeg、git…）、CosyVoice 原始碼與模型權重、pyannote 模型、現成的 Python 環境，各自是「已找到（在哪）」還是「沒有，會安裝」。最後一段「**要自己準備的**」列出安裝腳本不會處理的三樣：Claude Code（WSL2 裡要另外裝一份）、Groq 金鑰、Hugging Face 登入；標「⚠️ 要自己準備」的照後面的說明處理（也見上一節「準備什麼」）。

**已經有的不會重裝**。如果你之前照別的說明裝過 CosyVoice（原始碼＋模型約 7GB），安裝時會直接沿用：在倉庫裡建一個捷徑（symlink）指到你原本的位置，原本的檔案不會被移動或覆蓋。沿用模型之前會先驗證關鍵檔案齊全、大小合理，驗不過才會自己下載。

沿用的版本跟我們測過的版本不同時，畫面上會提醒，先跑跑看即可。想忽略偵測、全部重新下載：

```bash
bash install.sh --force-download
```

裝好之後，`bookclub doctor` 最後會顯示「現在用的原始碼與模型在哪裡」，排錯時看得出來是倉庫自己的還是沿用別處的。

### 正式安裝

```bash
cd ~/Downloads/bookclub-edit    # 或你 clone 下來的位置
bash install.sh
```

同一份腳本在 **macOS** 與 **Linux（含 Windows 的 WSL2 Ubuntu）** 都能跑，會自己判斷平台：macOS 用 Homebrew，Linux 用 apt-get 安裝 ffmpeg、sox、git、build-essential、curl、unzip，`uv` 用官方安裝指令。Linux 安裝系統套件那一步需要系統管理員權限，畫面上會跳出密碼提示。不是 Debian／Ubuntu 系統的話，腳本會列出需要的套件請你自行安裝。

`install.sh` 會依序做：檢查系統與空間 → 裝 Homebrew 套件（ffmpeg、uv）→ 建立 Python 3.11 虛擬環境（`.venv/`）→ 裝 Python 套件與 `bookclub` 指令 → 抓聲音生成引擎 CosyVoice 原始碼 → 下載三個 AI 模型 → 建立 `~/讀書會剪輯資料/` 資料夾（並複製 `profile.example/` 的範例檔進去）→ 建 Claude Code 的 skill 捷徑 → 跑一次環境健檢。**可以重複執行**：已經做過的步驟會自動跳過，不會重複下載，也不會刪掉已經調整過的設定。第一次安裝依網路速度可能要半小時以上，大部分時間花在下載模型。

**WSL2**：2026-09-29 已在 Windows 11＋WSL2（Ubuntu 26.04）實測，4 分半全自動裝完、中間不用人介入。沒有 NVIDIA 顯示卡時，腳本會裝只用處理器的 torch（CUDA 版多下載約 2.8GB 用不到的套件）。`uv` 裝完如果找不到，開新終端機再重跑。ModelScope 限流時（`[403] 操作过于频繁`）腳本會重試後先略過，下一步 `models download` 會補上。

### 裝完之後（第一次才要做）

1. **登入 Hugging Face**（用上一節第 4 項建的 Read 金鑰；金鑰不要貼給 AI）：
   ```bash
   .venv/bin/hf auth login
   ```
2. **下載分辨說話者的模型**（約十幾秒）：
   ```bash
   .venv/bin/bookclub models download
   ```
3. **匯入設定包**（名冊、匿名聲線等，向宇軒拿）：
   ```bash
   .venv/bin/bookclub profile import 設定包.zip
   ```
4. **環境健檢**，必要項目全部 ✅ 才開始用；❌ 的項目畫面上有修法：
   ```bash
   .venv/bin/bookclub doctor --claude
   ```
   `--claude` 會實際叫一次 Claude，確認登入過、叫得到。

## 5. 怎麼用

**平常操作都在網頁上**：

1. 雙擊「啟動.command」（macOS；WSL2 在終端機跑 `.venv/bin/bookclub serve`），瀏覽器開 <http://localhost:8766>。伺服器記得上次在做哪支影片，重開後自動接回
2. 「總覽」選影片、按「開始分析」（在影片旁邊建 `<影片檔名>_剪輯工作區/`；做到一半的會接著做）
3. 照左側步驟列走：0 初始化設定（人工，第一次才要）→ 1 影片分析（AI）→ 2 挑選老師參考聲音片段（人工）→ 3 覆核工作台（人工：先做開始前 4 件事，再逐筆通過）→ 4 AI 執行（AI：可以按「停止」，下次接著做；跑的時候第 3 步只能看不能改）→ 5 成品檢查（人工：全部通過、整片看過 100% 才能輸出）
4. 存檔失敗時（例如伺服器被關掉），畫面最上面會出現紅色橫幅，重新整理再改一次

下面是每一步的細節與終端機指令（測試、除錯用）。範例路徑請換成自己實際的檔案位置。指令都用虛擬環境裡的 `bookclub`：`.venv/bin/bookclub`。

**環境健檢**：檢查有沒有裝好、模型在不在、金鑰有沒有設定。

```bash
.venv/bin/bookclub doctor
```

**流程第 1 步一次跑完**：轉文字 → 段落分析（Claude）與認老師同時跑 → 合併判斷 → 找重疊 → 挑參考音 → 找姓名 → 學員段落認人，結果都寫進工作區資料夾。Claude 叫不到時會印警告、改用純聲紋判斷繼續跑。

```bash
.venv/bin/bookclub run analyze ~/讀書會剪輯資料/影片/第1堂.mp4 ~/讀書會剪輯資料/工作區/第1堂 --roster ~/讀書會剪輯資料/名冊.csv --sensitive ~/讀書會剪輯資料/敏感詞.csv
```

**單獨挑老師參考音**（`run analyze` 已經包含這步，這是要單獨重跑或測試時用）：

```bash
.venv/bin/bookclub ref pick ~/讀書會剪輯資料/影片/第1堂.mp4 ~/讀書會剪輯資料/工作區/第1堂
```

**選定某一個參考音候選**，存成正式的 `ref.wav`／`ref.txt`（`<名次>` 是 `ref pick` 推薦清單裡的第幾名，逐字稿先聽過修正好存成檔案再帶進去）：

```bash
.venv/bin/bookclub ref use ~/讀書會剪輯資料/工作區/第1堂 1 --text-file 修正後逐字稿.txt
```

參考音候選（10-01 起）是 48kHz、16 位元、單聲道 WAV：保留原片 8000 赫茲以上的高音，雙聲道用平均合成單聲道，音量跟直接播原片一樣。以前的候選是 16kHz、雙聲道相加（高音被切掉、大聲 3 分貝）。挑選的方法、門檻、停頓壓縮都沒變。

**舊工作區的候選換成新格式**（不重挑、不呼叫 Groq、不載入模型；逐字稿不動）：

```bash
.venv/bin/bookclub ref recut ~/讀書會剪輯資料/工作區/第1堂            # 原片預設用挑選紀錄.json 記的位置
.venv/bin/bookclub ref recut ~/讀書會剪輯資料/工作區/第1堂 --video 原片.mp4
```

- 照 `參考音/候選.json` 記的時間重切；舊的候選音檔先複製到 `參考音/舊候選備份_<時間>/`，不刪任何檔案。已經是新格式的略過，可以重跑
- 重切出來的長度跟紀錄差超過 0.25 秒（切點換到別的停頓、逐字稿可能對不上）的那一個不換，會印出來
- **已選定的 `ref.wav` 不會自動換**：換了之後老師的句子都要重新生成。要改用新的，到網頁第 2 步重新選定（已選定的那一個按「存逐字稿（繼續用這一個）」也會換上新的音檔），或再跑一次 `ref use`

**開本機網頁**（第 0～5 步都可以操作；左側步驟列每步標 AI／人工，按「«」收合、「»」展開，會記得上次的狀態）：

```bash
.venv/bin/bookclub serve
```

網址預設是 <http://localhost:8766>，會自動開瀏覽器（加 `--no-open` 不自動開）。不帶工作區時，在「總覽」選影片（網頁內的資料夾瀏覽，只能選家目錄底下的檔案），按「開始分析」才在影片旁邊建 `<影片檔名>_剪輯工作區/` 開跑（專案清單記在 `~/讀書會剪輯資料/專案清單.json`）；同一支影片做到一半的，按開始分析會接著做。已有的專案在總覽點「切換」。舊用法 `bookclub serve <工作區>` 照樣能用。也可以雙擊「啟動.command」（macOS；WSL2 直接用上面的指令）。Groq 金鑰設在 `~/.zshrc` 的話，要從 zsh 終端機或「啟動.command」開，伺服器才讀得到金鑰；讀不到時總覽會提醒。

**初始化設定與設定包**（第 0 步，跨專案共用，名冊只要一份）：

```bash
.venv/bin/bookclub profile export
```

```bash
.venv/bin/bookclub profile import 設定包.zip
```

合併規則：每個清單以第一欄當鑰匙，新的加進去、已經有的不動；同一鑰匙內容不同，保留本機的並列出衝突。

**用老師的 AI 聲音重念句子**（流程第 4 步的一部分）：先用 `ref use` 選定參考音，再準備一份句子清單。`.txt` 一行一句；要放回原片時間的話用 `.json`，每句附原片時間格：

```json
[{"id": "T4", "text": "如果我們從科學來看……", "slot": [5002.12, 5019.68]}]
```

```bash
.venv/bin/bookclub gen teacher ~/讀書會剪輯資料/工作區/第1堂 句子.json
```

每句用固定種子 42 生成，生成完用 Groq 轉回文字檢查：念錯、漏字就換種子重來。最多試 3 次，還是不過的標「要人聽」。

有時間格的句子，會做出幾種放回時間格的版本讓人挑：**插入停頓**（用逐字對位模型找出老師原本在哪裡停頓，在生成的聲音補上空白，只補在標點的位置，落在句子中間的停頓移到最近的標點；開口時間也對齊原片）、**補靜音**（一口氣念完，後面補空白）、**拉長**（整段放慢，最多到 0.85 倍）；前面幾種長度都差超過 15% 時，才會**改語速重生成**。`slot` 有給、`text` 不給的話，會照原片那段的逐字稿念（含老師重複的字）。結果在工作區的 `生成/老師/`，紀錄在 `生成/老師紀錄.json`（格式見 `docs/工作區格式.md`）。中斷後重跑會沿用已經生成好的句子；加 `--redo` 全部重做，加 `--no-check` 不做內容檢查，加 `--no-pauses` 不做插入停頓。

**發音對照表**（`~/讀書會剪輯資料/發音對照表.csv`，欄位：`原字`、`生成用`、`原因`、`建立日期`）：模型的口音不完全是台灣口音，有些詞會念偏（例如「愉快」念成「玉快」）。把念偏的詞跟「念起來比較接近台灣口音的寫法」寫進這份表（「愉快」→「魚快」），生成前會自動替換。只影響送進模型念的文字，內容檢查、對位都還是用原本的文字；改了對照表，用到那個詞的句子下次會自動重新生成。範例在 `profile.example/發音對照表.csv`。

**處理老師提到名字的地方**（第 3 步覆核完之後）：照每筆的做法（直接消音／整句換掉／只換名字）排出計畫，需要生成的交給老師 AI 聲音，再組出新聲音軌：

```bash
.venv/bin/bookclub gen names ~/讀書會剪輯資料/工作區/第1堂
.venv/bin/bookclub render audio ~/讀書會剪輯資料/工作區/第1堂
```

- 覆核標成「不是名字」「是地名」的會略過；同一句有好幾個名字要整句換掉時，合成一次生成
- 生成用的句子清單只含代號，不含本名；句子裡找不到比對到的字的，列在「要人處理」
- `render audio` 從原片重新抽 48kHz 聲音，換聲音的地方音量對齊原本那段、接縫交叉淡入淡出；消音的地方墊前後 20 秒內最安靜的底噪
- 產出在工作區的 `輸出/`：`新聲音軌.wav`（跟原片等長，交給剪輯軟體換掉原本的聲音）、`處理前後.html`（每一筆處理前／處理後各前後多 2 秒的試聽，給第 5 步成品檢查）
- 測試時可以只處理幾筆：`gen names <工作區> --only 3,9,13`

學員段落重念、組裝一段影片（0.1.7，測試版，終端機指令）：

- `gen students`：學員段落照句子接成 8～20 秒一段，用匿名聲線（`~/讀書會剪輯資料/聲線/男聲_暫定.wav`、`女聲_暫定.wav`，逐字稿同檔名 `.txt`）重念；男聲或女聲照名冊性別，名冊沒有就用原音估基頻。可以中斷續跑
- `render video`：換聲音（音量對齊、墊環境底噪）、刪除確認刪除的段落、比時間格長太多的學員段落停格補長、模糊示範，輸出三種做法比速度（`--methods hw,sw,smart`）。`--label` 另外輸出標字試看版：AI 處理過的時段左上角有標籤、生成的時段下方是餵給模型的文字。同時產出處理標記清單（`輸出/處理標記_<範圍>.html`），列出每一處 AI 做了什麼

**覆核工作台**（第 3 步）：`run analyze` 跑完之後開網頁第 3 步。

- **開始前 4 件事**（一進來先做，做完按「開始逐筆看」；之後可以從頂端回來改）：① 建議刪除段落（影片分析找到的開頭空白、結尾道別、念聊天區留言、小組討論前後、技術問題，逐段確認刪除或不刪）② 學員是誰（左邊每位「學員 N」試聽、選本名，最後一個選項是老師；右邊每個本名在這一集用哪個英文代號，可以自動配）③ 名冊上沒有的名字（這一集提到的其他人名：換成代號、是上面的學員、不是名字、不用處理）④ 誰保留原聲（只有同意的學員）。做完之後，落在確認刪除範圍裡的項目、保留原聲學員的學員段落自動標「不用處理」；保留原聲的學員講到名字會列成「學員提到名字」（預設直接消音，可選換成代號：用他自己的聲音重念那一句）
- 上半部：左邊影片、時間列（跳到時間、播放速度）、整支時間軸（老師灰、學員綠、冥想導讀淡藍；名字、重疊、刪除標記）；右邊「目前這一筆」：內容、藍底的建議＋一行原因、通過／改做法／上一筆／下一筆
- 下半部：篩選（全部／還沒確認／學員段落／名字／重疊／建議刪除）＋一行一筆的清單，點一行就換到右邊
- **每一筆一開始就有建議**，看過沒問題按「通過」：學員段落的逐字稿已經把名冊上的名字換成代號（換過的字標出來）；老師提到名字預設整句換掉；重疊照規則給建議（保留原聲學員→不用改、一來一往交接→兩邊都重生成前後排開、學員在老師話裡附和→只留老師原聲學員消音、老師在學員話裡短短回應→只留學員）
- 播放完全由人控制；播到下一筆的地方，右邊自動換過去（正在打字時不換）。按「通過」只標通過、影片照常播；上一筆／下一筆讓影片跳到那筆前 2 秒
- 「改做法」展開全部做法（名字：只換名字、直接消音、標記不是名字；重疊：六種做法與排法；學員段落：改說話者、併入上一段、從游標處切開、聽不清楚問老師⋯⋯）
- **＋新增修改**（時間軸下面，09-29 取代 I／O 標起訖）：選類型（刪除段落、局部消音、漏抓的學員發言、漏抓的「老師提到名字」、漏抓的重疊），起點終點各一格，三種填法：直接打時間（`43:15.2`）、按「用目前播放位置」、按 ±0.1 秒微調；「試聽這段」播到終點自動停。按「新增」後時間自動對齊到小數點以下，畫面顯示「你標的 → 對齊後」：刪除段落、局部消音對齊附近的安靜處；老師提到名字對齊逐字稿裡字的時間（前後留一點停頓，要選換成哪個代號）；學員發言、重疊對齊句子邊界；附近找不到可以對齊的地方就保留你標的時間、標「沒對齊」。新增的項目在清單裡標「人工新增」。已經有的項目按卡片上的「改時間」，用同一個面板改
- 快捷鍵：Enter 通過（逐字稿裡 Shift＋Enter 換行）、E 改做法、↑／↓ 上一筆／下一筆、空白鍵播放暫停、J／L 前後 5 秒、I／O 把目前時間填進「新增修改」的起點／終點、Esc（文字框裡）從頭播這一筆；頂端「快捷鍵」按鈕可以展開說明

- **每一段各自一支程式跑**（10-01，8GB 的 Mac 用）：同一支程式裡換步驟、換聲線時，前一個模型佔的記憶體不一定還給系統，兩個模型疊在一起會把記憶體撐爆（10-01 夜間第一堂：系統拿硬碟頂替的量衝到 11 GB、程式沒留訊息就結束）。現在 `run execute`（網頁「開始執行」）自己不載入模型，一段一段開子程式（`bookclub run part`，平常不用自己打），那一段做完程式就結束、記憶體一定還回去；任何時候記憶體裡最多一個大模型：
  - 老師名字：「生成」（生成模型）→「插入停頓」（逐字對位模型）→「收尾」（長度還是不過才改語速重生成，要的話才載入生成模型；放回時間格、寫紀錄），各一支
  - 學員重念：每個聲線一支「生成」→ 全部聲線一支「插入停頓」（對位模型只載入一次）→ 每個聲線一支「收尾」
  - 保留原聲學員講到名字：同上，以學員分（每位用自己的聲音）
  - 組裝：一支
  - 子程式的訊息一行一行即時出現在網頁訊息列與終端機；網頁「說明」欄寫跑到第幾支。每一支結束時把記憶體高峰、swap 最高、硬碟最低記在 `生成/子程式紀錄.jsonl`（也在 `生成/執行進度.json` 每一步的「子程式」）
  - 子程式出錯：那一步標失敗，訊息帶子程式最後幾行。被系統結束、沒有錯誤訊息（多半是記憶體不夠）：訊息寫明，等 30 秒重試一次，再不行才標失敗；做好的留在快取，不重做
  - **硬碟、記憶體不夠就停**：每一支開始前、跑的過程中約每 20 秒看一次。開始前硬碟可用要 5 GB 以上；跑的過程中硬碟低於 2.5 GB、或 swap（記憶體不夠時系統拿硬碟頂替的量，只有 Mac 讀得到）高於 8.5 GB，就請它做完目前這一句再停，訊息寫明是哪一個數字、現在多少、門檻多少、怎麼處理。門檻在 `settings.toml` 的 `[thresholds]`（`execute_min_disk_gb_start`、`execute_min_disk_gb`、`execute_max_swap_gb`）
  - **跑之前先關掉瀏覽器其他分頁與用不到的程式**：10-01 夜間同時跑別的事，老師那一步平均每 1 秒聲音花 23 秒；只跑一件事 7 秒
  - 個別指令（`gen names`、`gen students`、`gen stunames`、`render video`）照舊在同一支程式裡跑完三個階段；8GB 的電腦建議用 `run execute`
- 每一步都可以中斷續跑，已經做過的跳過（名字的每一句都生成好了、範圍內學員段落都生成過且文字沒變、成品比覆核與生成結果新）；進度記在 `生成/執行進度.json`
- 開始前先檢查缺什麼（逐字稿、段落分析、老師參考音、匿名聲線、原片），缺了直接說，不會跑到一半才失敗
- 情境：老師已經自己看完全片、挑好參考聲音，想直接請 AI 做。**第 1 步轉文字還是要跑**（學員的話要照逐字稿重念，電腦自動）；**第 2 步的老師參考音要選好**、會出現的名字都要有英文代號（前置檢查會擋；缺代號時頁面上有「幫還沒代號的自動配」）；能省掉的是第 3 步逐筆覆核的人工，沒覆核的話照第 1 步的建議做
- 網頁第 4 步：各類「完成／總數」與「已生成 N／共 M 句」（每生成一次就更新）、預估剩餘時間；「停止」會等目前這一句生成完才停（組裝中按的話等組裝做完），做好的都留著；伺服器跑到一半被關掉，下次開會顯示「中斷」，按開始執行接著做
- 選項：`--start 37:00 --end 55:23`（只做一段）、`--methods hw,sw,smart`（組裝的輸出做法，預設 sw 整段軟體編碼；hw 硬體編碼只有 Mac、smart 只重做片段）、`--only 組裝`（只跑某幾步）
- 還沒做：匯入老師的標記清單（要先確認老師標記是文字清單、網頁標記、還是剪輯軟體的標記點；參考聲音是給音檔還是時間點）

組裝（`render video`、`render audio`）做完會自動寫 **AI 處理紀錄** `生成/處理紀錄.json`：每個動作的原片起訖、成品起訖（刪除、停格之後）、做了什麼、對應第 3 步哪一筆、用了哪個檔案；並把原片聲音和新聲音每 20 毫秒比一次，列出「聲音變了、但沒有紀錄」的地方（`未登記的變動`），第 5 步要人確認。

**成品檢查**（第 5 步，09-29 原本第 5 步逐筆覆核＋第 6 步整片檢查合成一步）：版面像第 3 步，左邊成品影片＋時間軸（AI 處理過的地方全部標出來），右邊目前這一筆；最上面固定一行「沒列在時間軸上的地方＝原片沒動」。

- **逐筆看**：每一筆切換「處理前／處理後」試聽（前後各多 2 秒），按「通過」或「退回重做」（要寫原因）
- **整片看**：記錄實際播過的地方（只算 2 倍速以下連續播的；拖過去跳過的、超過 2 倍速快轉的不算，09-29 宇軒），顯示「已經看過全片的 x%」；看到問題寫一句原因、按「這裡有問題」，就在目前時間建一筆退回
- **沒登記的變動**另列一區，一處一處確認「沒問題」或「退回重做」
- 按「送回 AI 重做（N 筆）」寫進 `覆核/成品檢查.json`；第 4 步頁面、終端機都看得到要重做哪幾筆：

- `生成/老師紀錄.json`（含要念的句子與轉回來的文字，可能有學員姓名）

- `名冊.csv`、`敏感詞.csv`、`名字排除清單.csv`

終端機輸出跟 `報告.md`／`分析結果.json` 只放統計數字與耗時，不含逐字稿或學員說的內容，這兩份可以放心回報、討論。

## 7. 速度參考

第一堂實測（影片 98 分鐘，MacBook Air M1，只用處理器沒有用顯示卡；09-26 新流程從頭跑三次）：

| 步驟 | 耗時 |
| --- | --- |
| 完整分析（`run analyze`，轉文字用快取） | 24–25 分鐘；從影片開始再加轉文字約 100 秒 |
| 轉文字 | 約 100 秒 |
| 段落分析（Claude，8 塊同時送）‖ 認老師（聲紋） | 同時跑，約 2.5 分鐘（Claude 157 秒、認老師 80–90 秒） |

| 找姓名 | 約 5 秒 |
| 學員段落認人 | 約 5 秒 |

找重疊是最花時間的一步。冥想引導、導讀段落改判老師後，要掃的聲音從 2814 秒降到約 2100 秒（少 25%）。

CosyVoice 生成老師聲音（`gen teacher`，26 秒參考音）：載入模型約 1.5 分鐘；之後短句（5 秒）每 1 秒聲音約需 25–30 秒運算，長句（12–16 秒）約 11–14 秒。第一堂 4 句、5 次生成共 14 分鐘。

09-29 第一堂 37:00–55:23 實測（MacBook Air M1）：學員重念（8–20 秒一段、約 14 秒匿名聲線參考音）每 1 秒聲音約 8.5 秒運算；老師名字整句（1–8 秒的短句）約 27 秒——短句的固定開銷分攤到比較少秒數。組裝 18 分鐘的範圍：整段硬體編碼約 3 分鐘、軟體編碼約 4 分鐘、只重做有動到的片段約 30 秒。

**Windows 11＋WSL2 實測**（2026-09-29，Intel Core Ultra 7 270K Plus 24 核心、WSL2 分到約 15GB 記憶體、沒有 NVIDIA 顯示卡，同一支第一堂 98 分鐘）：

## 8. 隱私與授權

- **影片、名冊、逐字稿都不進這個倉庫**：這些檔案根本不在倉庫資料夾路徑下，統一放在 `~/讀書會剪輯資料/`（見上面「產出在哪」）。
- **雲端只用 Groq 語音辨識**：轉文字這一步會把音訊片段送到 Groq；`gen teacher` 的內容檢查會把生成出來的老師 AI 聲音送到 Groq 轉回文字（加 `--no-check` 就不送）。其餘步驟（分辨誰在說話、找重疊、找姓名候選、聲音生成本身）都在本機跑，不上傳。
- **模型授權**：聲音生成引擎 CosyVoice3 是 Apache-2.0 授權；分辨誰在說話用的 pyannote 可商用；另一個原本評估過的聲音生成方案 F5-TTS 因為授權不可商用，所以沒有採用。
- **倉庫本身**：這個程式碼倉庫用 [MIT License](LICENSE)。
