# 工作區檔案格式

一支影片一個工作區資料夾（例如 `~/讀書會剪輯資料/工作區/<名稱>/`）。流程第 1 步
「轉文字與分析」的四個零件（`bookclub/transcribe.py`、`speakers.py`、
`overlap.py`、`names.py`）跟 `bookclub/refpick.py`（挑老師參考音）都讀寫同一個
工作區，檔名寫死在 `bookclub/workdir.py`，程式要用路徑都從那支模組問，不要
自己組字串。

串起來跑：`bookclub run analyze <影片> <工作區> [--roster 名冊.csv] [--sensitive 敏感詞.csv] [--exclusions 名字排除清單.csv] [--skip-overlap]`
（見 `bookclub/analyze.py`）。每個零件自己的快取檔案存在就跳過，可以中斷續跑。
`--exclusions` 不給就預設抓 `--roster` 同一層目錄下的「名字排除清單.csv」。

隱私提醒：`transcript/`、`說話者判斷.json`、`名字候選.json`、`名字候選/`、
`名字覆核.html` 這幾個地方會含學員分享內容、老師提到的名字。這些檔案可以留在
工作區裡給覆核網頁用，但不要整份貼進對話、回報或 commit 訊息——內容只在檔案
裡，terminal 輸出跟 `報告.md` 只放統計數字。

## 檔案總覽

| 路徑 | 誰寫 | 內容 | 對應 `workdir.py` |
| --- | --- | --- | --- |
| `audio.flac` | transcribe（`refpick` 若先跑到會沿用同一個檔案） | 整支影片抽出來的音軌，16kHz 單聲道 flac | `audio_path()` |
| `chunks/` | transcribe、refpick、overlap 共用資料夾 | 送去 Groq／pyannote 的音訊分塊。transcribe 用 4 位數前綴 `chunk_0000.flac`…（VAD 人聲區段接起來，挖掉靜音），refpick 自己另外用 2 位數 `00.flac`…（固定 10 分鐘一段），兩邊檔名不會互踩 | `chunks_dir()` |
| `transcript/` | transcribe、refpick 共用資料夾 | 見下方「`transcript/` 資料夾」 | `transcript_dir()`、`merged_transcript_path()` |
| `說話者判斷.json` | speakers（沿用 `refpick._step3_speaker_classify` 的快取） | 見下方 | `speakers_path()` |
| `重疊.json` | overlap | 見下方 | `overlap_path()` |
| `重疊/` | overlap | 每個掃描區域切出來的音檔＋pyannote 的 RTTM 快取（`區域0000.flac`／`.rttm`…），可續跑用，不是給人看的 | （模組內部路徑，非 `workdir.py` 公開函式） |
| `參考音/` | `bookclub/refpick.py`（`pick_reference`） | 候選音檔／逐字稿、`候選.json`、`挑選紀錄.json`、`試聽.html`——格式見 `bookclub/refpick.py` 開頭的說明，這支文件不重複寫 | `ref_dir()` |
| `名字候選.json` | names | 見下方 | `names_path()` |
| `名字候選/` | names、namespage | 每筆候選名字前後各 2 秒的原音小段（`0000_12.3s.wav`…）＋覆核頁另外切的消音版（`0000_12.3s_消音.wav`…），供覆核試聽 | `name_candidates_dir()` |
| `名字覆核.html` | namespage（`run analyze` 跑完找名字自動產生） | 靜態覆核頁，見下方「`名字覆核.html`」 | （工作區根目錄，非 `workdir.py` 公開函式；固定檔名） |
| `分析結果.json` | analyze（串流程） | 彙整索引：各步驟耗時、統計數字（句數、老師佔比、重疊數、候選數…），不放逐字稿 | `analysis_result_path()` |
| `報告.md` | analyze（串流程） | 給人看的報告，只放統計與時間，不放逐字稿或學員說的內容 | `report_path()` |
| `名字覆核決定.json` | `bookclub/server.py`（網頁第 4 步「標記覆核」，`POST /api/names/mark`） | 見下方「`名字覆核決定.json`」 | （工作區根目錄，非 `workdir.py` 公開函式；固定檔名） |
| `web快取/` | `bookclub/server.py`（`GET /api/audio?start=&end=`） | 網頁播放器用 `start`／`end`（原片絕對秒數）指定要聽的片段時，即時用 ffmpeg 從 `audio.flac` 切出來的音檔快取，檔名 `{start}_{end}.wav`（兩位小數），同樣參數第二次直接給快取檔，不重切。可以整批刪掉，之後聽的時候會自動重切 | （工作區根目錄，非 `workdir.py` 公開函式） |

## `transcript/` 資料夾

- `chunk_0000.json`、`chunk_0001.json`…：transcribe 每一塊（VAD 人聲區段接起來、
  最長 18 分鐘）呼叫 Groq `whisper-large-v3` 的原始回應（`verbose_json`，含
  `words`／`segments`），時間是「這一塊接起來後」的相對時間，還沒換算回原影片。
  中斷續跑用；已存在就不重打 Groq。
- `merged.json`：transcribe 的最終輸出，`bookclub/transcribe.py` 的
  `transcribe()` 回傳值就是這個檔案的內容。**這是流程第 1 步後面三個零件
  （認老師、找重疊、找名字）真正在讀的資料**，欄位：

  | 欄位 | 內容 |
  | --- | --- |
  | `source` | 影片路徑 |
  | `duration` | 影片音訊總長（秒） |
  | `sentences` | `[{id, start, end, text, avg_logprob}, ...]`，時間已換算回原影片絕對秒數，文字已轉台灣繁體 |
  | `words` | `[{word, start, end}, ...]`，原影片絕對秒數 |
  | `silence_map` | `[{start, end}, ...]`，VAD 判定的靜音區段（原影片絕對秒數），debug／統計用 |
  | `elapsed` | 這次轉文字各步驟耗時（抽音、VAD 掃描、轉文字各段與總計、轉繁體） |

  `merged.json` 已存在就直接讀出來回傳，不重跑 VAD、不打 Groq——重跑整個
  `run analyze` 或單獨測試轉文字都很快。

- refpick 自己的 `00.json`、`01.json`…（2 位數、固定 10 分鐘一段）：
  `bookclub/refpick.py` 內部「挑老師參考音」用的轉文字快取，跟上面 transcribe
  的塊是分開的兩份轉文字結果（切法不同），但都是同一支影片、同一份 Groq
  額度花費，所以刻意放在同一個 `transcript/` 資料夾裡方便管理。

## `說話者判斷.json`（speakers）

`bookclub/speakers.py` 的 `classify_speakers()` 直接呼叫
`bookclub/refpick.py` 的 `_step3_speaker_classify()`，共用同一份快取——這支
檔案 `refpick.pick_reference()` 之後也會讀到，不會重算一次。

| 欄位 | 內容 |
| --- | --- |
| `sentences` | 每句附上 `sim`（跟老師聲紋的餘弦相似度）與 `label`（`老師`／`不是老師`／`不確定`／`太短`） |
| `cluster_info.分群數` | 階層式分群後的群數 |
| `cluster_info.各群秒數` | 各群總發言秒數（由多到少） |
| `cluster_info.老師群編號` | 發言秒數最多那一群的編號 |
| `cluster_info.老師群佔可比對總秒數比例` | 老師群秒數 ÷ 全部可抽聲紋句子的總秒數 |
| `cluster_info.老師聲紋中心` | 老師群的平均聲紋（正規化過），overlap／refpick 認老師都靠這個向量 |
| `scan_regions` | **speakers.py 額外算的**：`[[start, end], ...]`，學員／不確定的句子前後各 `overlap_scan_pad_s` 秒、合併重疊後的區域——下一步「找重疊」只在這些範圍跑 pyannote |
| `scan_pad_s` | 算 `scan_regions` 實際用的 pad 秒數（來自 `~/讀書會剪輯資料/settings.toml` 的 `overlap.scan_pad_s`，預設 3） |

## `重疊.json`（overlap）

| 欄位 | 內容 |
| --- | --- |
| `overlaps` | 每處重疊一筆：`start`／`end`／`length`（原影片絕對秒數與長度）、`speakers`（`[{label, role, sim}, ...]`，`role` 是 `老師`／`不是老師`／`不確定`）、`已自動跳過`（bool）、`原因`（跳過理由或 `null`）、`區域`（對應 `重疊/區域NNNN.rttm`） |
| `重疊數` | `overlaps` 總筆數（含已自動跳過的） |
| `已自動跳過數` | `已自動跳過 == true` 的筆數 |
| `掃描區域數`、`掃描總秒數` | 這次實際送進 pyannote 的區域數與總秒數 |
| `elapsed` | 這一步總耗時（秒） |

自動跳過只套用兩條規則（02 規格，2026-09-20 定案）：兩位學員之間的重疊；
老師講話時學員的短附和（短於 `thresholds.echo_overlap_max_s` 秒、且落在老師
連續發言區間內部）。跳過的紀錄還在清單裡，不是刪掉，覆核網頁之後可以一鍵救回。

## `名字候選.json`（names）

| 欄位 | 內容 |
| --- | --- |
| `candidates[].start`／`end` | 名字那一小段的建議切點（原影片絕對秒數，已用音量修正過） |
| `candidates[].sentence` | 名字所在的整句逐字稿（個資，見檔案開頭的隱私提醒） |
| `candidates[].name`／`canonical`／`代號` | 命中的寫法／名冊上的本名／對應的英文代號（敏感詞則是替代詞） |
| `candidates[].matched_text` | 逐字稿裡實際被比對到的那幾個字（不一定等於 `name`，A1／A2 是放寬讀音比對，字面可能不同；也不保證是 `sentence` 裡的原字面——見下方「已知落差」） |
| `candidates[].敏感詞` | `true` 表示這筆是敏感詞比對（只做精確比對），不是學員姓名 |
| `candidates[].比對層級` | `精確`／`A1`（同音不同調）／`A2`（放寬台灣口音常混的音） |
| `candidates[].信心` | `高`（精確）／`中`（A1）／`低`（A2）——只看讀音比對層級，跟下面的「切點信心」是兩件事；低信心仍然是候選，只是要優先覆核（09-24 定案：礁溪第一堂 18 筆誤抓全部出在 A2/低信心） |
| `candidates[].位置` | `句首`／`句中`／`句尾`／`句首句尾` |
| `candidates[].建議做法` | `直接消音`／`只換名字`／`整句換掉` |
| `candidates[].原因` | 建議「整句換掉」時的原因（例如「找不到乾淨切點」），其他做法是 `null` |
| `candidates[].切點信心` | `雙邊乾淨`／`單邊乾淨`／`都不乾淨`——頭尾兩個切點各自有沒有找到乾淨停頓 |
| `candidates[].建議緩衝秒數` | 切點確定是乾淨停頓時，建議再留的前後緩衝秒數 |
| `candidates[].候選音檔` | 相對工作區路徑，指到 `名字候選/` 底下前後各 2 秒的試聽片段 |
| `已自動排除` | 命中「名字排除清單」而沒有進 `candidates` 的筆數，每筆 `{start, end, sentence_id, matched_text, 原因}`——不含整句逐字稿 |
| `排除清單` | 讀到的 `名字排除清單.csv` 原始內容（`詞`／`原因`／`建立日期`），供覆核頁顯示「這次擋掉了什麼」 |
| `統計` | `總筆數`、`各層級筆數`、`信心分布`、`各建議做法筆數`、`切點信心分布`、`已自動排除數`——只有數字，這是唯一可以安心印在終端機／報告裡的部分 |

已知落差（09-24 發現，不是這次要修的 bug，記錄下來給下次排錯用）：`matched_text` 是從 Groq 的逐字（`words`）時間軸比對出來的，`sentence` 欄位是 Groq 的整句（`sentences`）文字——兩邊是分開的兩份輸出，偶爾字面對不上（例如句子邊界的字詞時間有重疊，或同音字取字不同），`matched_text` 可能不是 `sentence` 裡逐字能找到的原字面。覆核頁在 `sentence` 裡精準比對不到 `matched_text` 時會退回概略標色（照「位置」標句首／句尾／句中一段），不是完全沒標。

## 名字排除清單.csv

宇軒逐筆聽過候選、確認「這不是名字」之後手動維護的清單，跟名冊、敏感詞放在
同一層目錄（`~/讀書會剪輯資料/名字排除清單.csv`）。欄位：`詞`（要擋的字串，
可以照原樣抄逐字稿，含標點也沒關係）、`原因`、`建立日期`。`names.py` 比對時
會先把詞跟候選的 `matched_text` 都拿掉標點與空白再比對，所以「風，風」寫進
清單也擋得到候選記下的「風風」。檔案不存在就是沒有排除清單，照常運作，不會
報錯。不會漏抓——只有 `matched_text` 完全命中（正規化後）才會被排除，不是
收緊比對門檻。

## 名字覆核.html

`bookclub/namespage.py`（`build_review_page`，`run analyze` 每次跑完找名字都會
重新產生一份，取代原本手寫在暫存資料夾的版本）根據 `名字候選.json` 產生的靜態
覆核頁，放在工作區根目錄，相對路徑引用 `名字候選/` 底下的音檔，離線、手機都能
開。內容：每筆候選的原片時間、整句逐字稿（`matched_text` 黃底標出）、比對到的
字／代號／位置／層級／信心／建議做法／切點信心、原音與消音版兩個播放器（消音版
新切在 `名字候選/`，檔名加 `_消音`）、三個勾選（不是名字／是地名／切點削到旁邊
的字）＋複製回報按鈕；頁面最上方列出已自動排除的筆數與清單內容；低信心（A2）
的筆數用底色與標籤標出來，方便優先覆核。這份頁面跟其他工作區檔案一樣含學員分享
內容，不要整份貼進對話或 commit。

切點做法（方案 1，宇軒 2026-09-23 定案）：以 Groq 的字層級時間為初值，往前往後
各找最多 0.3 秒，用音量找最近的停頓修正切點；切點不會落在相鄰的字裡面。找不到
乾淨切點時，建議做法一律改成「整句換掉」並標記原因，不再依句首句尾判斷。

`bookclub serve` 開的網頁第 4 步「標記覆核」是這份靜態頁的互動版：一樣讀
`名字候選.json`，一樣呼叫 `bookclub/namespage.py` 的 `_highlight_sentence`／
`_mute_clip` 標黃底與切消音版，差別是勾選會即時 `POST /api/names/mark` 存進
`名字覆核決定.json`（見下），不用「複製回報」貼給宇軒了；`名字覆核.html` 這份
靜態頁還是照常產生，離線／手機單純聽打勾還是能用。

## 名字覆核決定.json

`bookclub/server.py`（`POST /api/names/mark`）寫的，記錄網頁第 4 步「標記覆核」
每一筆候選勾了什麼。格式：`{候選id字串: {tags, note, 更新時間}}`，`候選id` 是
該筆在目前 `名字候選.json` 的 `candidates` 陣列裡的順位（1 起算）——只有重跑
找名字、候選清單增減或重新排序時，`id` 才會對不上舊的決定紀錄，這一輪先這樣
做。`tags` 是勾選的項目（`不是名字`／`是地名`／`切點削到旁邊的字`，可以複選），
`note` 是備註欄文字。同一個 `id` 再勾一次會整筆覆蓋（不是疊加），存檔是累積
式——重跑 `/api/names` 會把這份決定紀錄併回候選清單的「已標記」欄位，網頁重新
整理不會遺失勾選狀態。`tags` 含「是地名」或「不是名字」時，會同時把該筆的
`matched_text` 追加進 `~/讀書會剪輯資料/名字排除清單.csv`（正規化後跟既有的詞
重複就不重寫），下次分析同一支或別支影片就會自動排除掉。這份檔案含學員分享
內容（`note`、間接透過 `matched_text` 影響的排除清單），跟 `名字候選.json` 一樣
不要整份貼進對話或 commit。
