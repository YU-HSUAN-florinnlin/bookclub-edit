# 工作區檔案格式

一支影片一個工作區資料夾。0.1.6 起網頁建在影片旁邊：`<影片所在資料夾>/<影片檔名>_剪輯工作區/`，專案清單記在 `~/讀書會剪輯資料/專案清單.json`（`{"專案": [路徑, ...]}`，總覽靠它列出、切換）；以前的工作區在 `~/讀書會剪輯資料/工作區/<名稱>/`，照樣能用。10-07 起 WSL2 在網頁選到 Windows 磁碟（`/mnt/<磁碟>/…`）上的影片時，先複製到 `~/讀書會剪輯資料/影片/`（同名同大小沿用、同名不同大小改名 `… (2).mp4`），工作區建在複製過來的那一份旁邊。流程第 1 步
「影片分析」的四個零件（`bookclub/transcribe.py`、`speakers.py`、
`overlap.py`、`names.py`）跟 `bookclub/refpick.py`（挑老師參考音）都讀寫同一個
工作區，檔名寫死在 `bookclub/workdir.py`，程式要用路徑都從那支模組問，不要
自己組字串。

串起來跑：`bookclub run analyze <影片> <工作區> [--roster 名冊.csv] [--sensitive 敏感詞.csv] [--exclusions 名字排除清單.csv] [--skip-overlap]`
（見 `bookclub/analyze.py`）。每個零件自己的快取檔案存在就跳過，可以中斷續跑。
`--exclusions` 不給就預設抓 `--roster` 同一層目錄下的「名字排除清單.csv」。

隱私提醒：`transcript/`、`說話者判斷.json`、`名字候選.json`、`名字候選/`、
`名字覆核.html` 這幾個地方會含學員分享內容、老師提到的名字。這些檔案可以留在
工作區裡給覆核網頁用，但不要整份貼進對話、回報或 commit 訊息——內容只在檔案
裡，terminal 輸出跟 `報告.md` 只放統計數字。

**AI 助手查工作區資料一律用 `bookclub inspect <工作區> <主題>`**（0.2.0b1 起，`bookclub/safeview.py`，
用法見 `docs/給AI助手-查工作區資料.md`）：只印時間、編號、數字、狀態，不要自己讀這些 JSON。

## `transcript/` 資料夾

- `chunk_0000.json`、`chunk_0001.json`…：transcribe 每一塊（VAD 人聲區段接起來、
  最長 18 分鐘）呼叫 Groq `whisper-large-v3` 的原始回應（`verbose_json`，含
  `words`／`segments`），時間是「這一塊接起來後」的相對時間，還沒換算回原影片。
  中斷續跑用；已存在就不重打 Groq。
- `whole_0000.json`、`whole_0001.json`…（10-04 #62 起，預設的「不挖停頓」做法）：整支每約 10 分鐘一塊（切點挑離 10 分鐘最近的安靜處），
  原封不動送 Groq、讓 Groq 自己斷句的原始回應；音檔是 `chunks/whole_0000.flac`…。一塊超過 Groq 上傳上限（25MB）時從安靜處再切一刀。
  回應裡另外記 `_轉文字做法`（`不挖停頓`）、`_塊起`／`_塊訖`（這一塊在原影片的起訖秒數）；做法或切點跟這次不一樣就重轉那一塊。
  上面的 `chunk_0000.json` 是舊做法（挖掉靜音），10-04 起只有舊工作區有；「保留一秒停頓」做法（已停用）轉的塊另記
  `_轉文字做法`＝`保留一秒停頓`、`_保留停頓秒數`（舊快取沒有這兩欄＝挖掉靜音、沒補空白）。
- `merged.json`：transcribe 的最終輸出，`bookclub/transcribe.py` 的
  `transcribe()` 回傳值就是這個檔案的內容。**這是流程第 1 步後面三個零件
  （認老師、找重疊、找名字）真正在讀的資料**，欄位：

  | 欄位 | 內容 |
  | --- | --- |
  | `source` | 影片路徑 |
  | `duration` | 影片音訊總長（秒） |
  | `sentences` | `[{id, start, end, text, avg_logprob}, ...]`，時間已換算回原影片絕對秒數，文字已轉台灣繁體 |
  | `words` | `[{word, start, end}, ...]`，原影片絕對秒數 |
  | `silence_map` | `[{start, end}, ...]`，VAD 判定的靜音區段（原影片絕對秒數），debug／統計用 |
  | `elapsed` | 這次轉文字各步驟耗時（抽音、VAD 掃描、轉文字各段與總計、轉繁體） |

  `run analyze` 或單獨測試轉文字都很快。

| `輸入指紋` | （09-29）這次掃描範圍（`scan_regions` 合併後、取到 0.1 秒）的指紋。之後說話者判斷改了、範圍不一樣時不自動重算（重疊已經接了人工覆核決定），回傳時多一個 `輸入改過`（提醒文字，不寫進檔案），分析結果的 `要注意` 會列出來；要重找就把 `重疊.json` 改名後重跑 |

自動跳過套用三條規則（前兩條 02 規格 2026-09-20 定案，第三條 09-26 加）：兩位學員之間的重疊；
老師講話時學員的短附和（短於 `thresholds.echo_overlap_max_s` 秒、且落在老師
連續發言區間內部）；重疊不到 0.05 秒（pyannote 的邊界誤差，第一堂有 6 筆 0.0 秒）。第三條不需要重跑 pyannote，
讀舊的 `重疊.json` 時也會套用（`overlap.apply_simple_filters`）。跳過的紀錄還在清單裡，不是刪掉，覆核網頁之後可以一鍵救回。

| `統計`（10-04 起多的） | `各來源筆數`（`{來源: 筆數}`，新找的才有）、`放寬範圍補找數`（舊工作區補掃時補到幾筆） |

| `輸入指紋` | （09-29）找名字時判成老師的句子（id＋文字）的指紋。之後說話者判斷或逐字稿改了、指紋不一樣時不自動重算（名字候選已經接了覆核決定），回傳時多 `輸入改過`（提醒文字，不寫進檔案），漏掉的名字請到第 3 步「＋新增修改」補 |
| `elapsed` | 這一步總耗時（秒） |

同一處只出一張卡（0.2.1b1 起）：`名字候選.json` 照舊每一筆都存（順位不變，覆核決定照順位對得上）；讀的時候（`review.effective_name_candidates` → `same_spot_groups`）同一句、起訖都差不到 0.05 秒的幾筆（名冊同一個寫法在兩列、讀音相近，同一處比中好幾個人）合成一張：留最準的當主卡（精確＞A1＞A2；聽到的字跟寫法一樣的優先；再照順位），其他併進主卡的 `也可能是`（第 3 步卡片上可以改用另一位，存在覆核決定的 `選的人`）。已經按過通過的不併、優先當主卡（舊工作區已確認的決定不動）。敏感詞不併。被併掉的那幾筆在處理計畫放進 `略過[]`（帶 `同一處`：主卡順位）。

已知落差（09-24 發現，不是這次要修的 bug，記錄下來給下次排錯用）：`matched_text` 是從 Groq 的逐字（`words`）時間軸比對出來的，`sentence` 欄位是 Groq 的整句（`sentences`）文字——兩邊是分開的兩份輸出，偶爾字面對不上（例如句子邊界的字詞時間有重疊，或同音字取字不同），`matched_text` 可能不是 `sentence` 裡逐字能找到的原字面。覆核頁在 `sentence` 裡精準比對不到 `matched_text` 時會退回概略標色（照「位置」標句首／句尾／句中一段），不是完全沒標。

## 名字排除清單.csv

開發者逐筆聽過候選、確認「這不是名字」之後手動維護的清單，跟名冊、敏感詞放在
同一層目錄（`~/讀書會剪輯資料/名字排除清單.csv`）。欄位：`詞`（要擋的字串，
可以照原樣抄逐字稿，含標點也沒關係）、`原因`、`建立日期`。`names.py` 比對時
會先把詞跟候選的 `matched_text` 都拿掉標點與空白再比對，所以「風，風」寫進
清單也擋得到候選記下的「風風」。檔案不存在就是沒有排除清單，照常運作，不會
報錯。不會漏抓——只有 `matched_text` 完全命中（正規化後）才會被排除，不是
收緊比對門檻。

## 名字覆核決定.json

`bookclub/review.py`（網頁第 3 步覆核工作台，`POST /api/review/name`）寫的（舊的 `POST /api/names/mark` 也寫這份），
記錄每一筆候選怎麼處理。格式：`{候選id字串: {做法, tags, note, 已確認, 更新時間}}`，`做法` 是
`整句換掉`／`只換名字`／`直接消音`（沒有這個欄位就當整句換掉，09-25 定案），`已確認` 是覆核工作台按了確認。`候選id` 是
該筆在目前 `名字候選.json` 的 `candidates` 陣列裡的順位（1 起算）——只有重跑
找名字、候選清單增減或重新排序時，`id` 才會對不上舊的決定紀錄，這一輪先這樣
做。`tags` 是勾選的項目（`不是名字`／`是地名`／`切點削到旁邊的字`，可以複選），
`note` 是備註欄文字。`選的人`（0.2.1b1 起）：同一處比中好幾個人、合成一張卡時，人選的是哪一位（名冊本名；沒有＝自動選的，比對最準的那一位），名字、代號換成那一位的。同一個 `id` 再勾一次會整筆覆蓋（不是疊加），存檔是累積
式——重跑 `/api/names` 會把這份決定紀錄併回候選清單的「已標記」欄位，網頁重新
整理不會遺失勾選狀態。`tags` 含「是地名」或「不是名字」時，會同時把該筆的
`matched_text` 追加進 `~/讀書會剪輯資料/名字排除清單.csv`（正規化後跟既有的詞
重複就不重寫），下次分析同一支或別支影片就會自動排除掉。這份檔案含學員分享
內容（`note`、間接透過 `matched_text` 影響的排除清單），跟 `名字候選.json` 一樣
不要整份貼進對話或 commit。

## `生成/名字處理計畫.json`、`生成/名字句子.json`（nameplan）

`bookclub gen names` 寫的。`名字句子.json` 是交給 `gen teacher` 的句子清單（`id`：整句換掉 `S<候選編號>`、只換名字 `N<候選編號>`；`text` 已換成代號，不含本名）。`名字處理計畫.json`：

| 欄位 | 內容 |
| --- | --- |
| `生成[]` | `id`、`text`、`slot`（整句換掉＝整句的時間；只換名字＝名字那一小段加緩衝）、`候選`（這一段處理了哪幾筆候選，同一句多個名字會合併） |
| `消音[]` | `候選`、`start`、`end`（名字那一小段加建議緩衝秒數） |
| `略過[]` | 覆核標成「不是名字」「是地名」的候選；落在剪掉的片段裡的；同一處合成一張卡、被併掉的（帶 `同一處`：主卡順位，0.2.1b1 起） |
| `要人處理[]` | 找不到所在句子、或句子裡找不到比對到的字，沒辦法自動換成代號的候選 |
| `涵蓋` | （有才寫，0.2.1b1 起）`{候選編號: 生成 id}`：這一筆整個落在另一筆**已通過**、整句換掉的重念範圍裡，由那一句處理（不列要人處理、併進那一句的 `候選`）。第 3 步卡片同一個規則顯示「已由〈那一筆〉涵蓋」；那一筆退回、改做法就不再涵蓋 |

同一句另一筆已經人改好要念的句子（`改稿`）時，這一筆在句子裡找不到比對到的字也併進那一句，不列要人處理（跟縮小範圍的做法一樣，0.2.1b1 起）。

做法：`名字覆核決定.json` 那一筆有 `做法` 欄位就用覆核的，沒有就**整句換掉**（09-25 定案；`名字候選.json` 的 `建議做法` 只在覆核時當參考）。整句換掉時照標點把 Groq 的半句擴成完整句子（`nameplan.expand_sentence`：前一段以逗號類結尾、也是老師、中間空白不超過 0.8 秒就接上，往後同理；整句不超過 25 秒），`生成[]` 多一個 `句子` 欄位記接了哪幾段。

舊版「匯入覆核結果」建的工作區（10-23 起這個功能已刪除）沒有 `名字候選.json`，`gen names` 照舊直接用 `覆核/覆核結果.json` 裡排好的計畫。

## `輸出/`、`生成/剪輯決策.json`（assemble）

`bookclub render audio` 寫的。`輸出/原聲音軌.wav` 是從原片抽出的 48kHz 單聲道聲音（組裝的來源，之後重跑沿用）；`輸出/新聲音軌.wav` 是處理後、跟原片等長的聲音；`輸出/處理前後/` 與 `處理前後.html` 是每一筆的試聽。`生成/剪輯決策.json` 記錄這次套用的動作（`類型` 換聲音／消音、`start`、`end`、`檔案`、`文字`、`候選`、`要人聽`）、警告（還沒生成、被較長的一筆蓋過）與統計。兩筆重疊時，時間長的蓋過短的。

## `生成/老師紀錄.json`（tts）

`bookclub gen teacher <工作區> <句子清單>` 寫的紀錄。句子清單格式見 `bookclub/tts.py` 的 `load_sentences()`（`.txt` 一行一句，或 `.json` 附原片時間格 `slot`）。每句生成照「種子 42 → 檢查 → 不過才重試」最多 3 次：內容（Groq 轉回文字跟原句比，相似度 < 0.85 算不過）不過就換種子；有時間格時先照原片停頓插入空白（`bookclub/pauses.py`，只補在標點的位置，不用重新生成），原始或插入停頓後的長度都跟時間格差 > `thresholds.length_tolerance`，才同一個種子改語速重生成。

| 欄位 | 內容 |
| --- | --- |
| `參考音`、`參考音逐字稿` | 這次用的參考音路徑與逐字稿；跟上次不同會全部重新生成 |
| `句子[].生成用文字`、`發音對照` | 套用 `~/讀書會剪輯資料/發音對照表.csv` 之後真正送進模型念的文字、用到哪幾條對照（例如 `愉快→魚快`）；對照表改了，這句下次會重新生成 |
| `句子[].id`／`text`／`slot`／`slot_s` | 句子編號（也是檔名）、要念的文字（繁體，程式自動轉簡體；有 `slot` 而沒給文字時，用原片那段的逐字稿）、原片時間格 |
| `句子[].嘗試[]` | 每次嘗試：`種子`、`語速`、`長度秒`、`插入停頓後長度秒`、`耗時秒`、`倍數`（耗時 ÷ 長度）、`轉回文字`、`內容相似度`、`內容通過`、`長度通過`、`聲紋相似度`（跟 `說話者判斷.json` 的老師聲紋中心比，只記錄、不淘汰） |
| `句子[].選定`、`檔案` | 選了第幾次、選定檔（`生成/老師/<id>.wav`） |
| `句子[].原片停頓`、`原聲檔案` | 有時間格、工作區有 `audio.flac` 才有：原片老師在哪個字後面停了幾秒（音量找停頓＋逐字對位模型對到字），與原片那一段的切檔 |
| `句子[].候選做法[]` | 有時間格才有，每種放回時間格的做法一筆：`版本`（插入停頓／補靜音／改語速重生成／拉長）、`來源第幾次`、`長度秒`、`放回做法`（`bookclub/fit.py` 的補靜音／微調語速／標紅）、`差異比例`、`atempo`、`原因`、`檔案`；插入停頓另有 `插入點`、`開頭位移秒` |
| `句子[].建議做法`、`放回時間格` | 候選做法裡能放進時間格的，照「插入停頓 → 補靜音 → 改語速重生成 → 拉長」的順序挑第一個；都不行就挑差距最小的並標「要人聽」。`放回時間格` 是那個做法的內容，檔案複製一份成 `生成/老師/<id>_放回時間格.wav` |
| `句子[].要人聽` | 內容或長度沒過、或放回時間格被標紅 |
| `統計` | 句數、要人聽句數、生成次數、總秒數、總耗時、平均倍數、載入模型秒數 |

`轉回文字` 與 `text` 可能含學員姓名（老師提到名字的句子），跟其他逐字稿一樣不要整份貼進對話或 commit。

## `生成/學員紀錄.json`（students）

跟 `生成/老師紀錄.json` 同一種每句格式（`id`、`text`、`生成用文字`、`發音對照`、`slot`、`嘗試[]`、`選定`、
`候選做法`、`建議做法`、`放回時間格`、`要人聽`），另外每段多：`段落`（學員段落 id）、`學員`、`聲線`（男／女）、
`參考音`（這段用的參考音路徑，換參考音就重生成）、`句子`（組成這段的逐字稿句子 id）、`換成代號`（名冊本名換了幾處）、
`文字來源`（建議稿／校對稿）、`角色`（學員）。最上層：`參考音`（男、女各一）、`學員聲線`、`統計`。
`放回時間格` 多一個 `來源檔案`（放回前、沒裁切的生成檔），比時間格長 15% 以上（`放回做法` 標紅）時組裝用它做停格補長。

切格（0.2.1b1 起）：只在句子之間、原片真的安靜 0.3 秒以上的地方切（量 `audio.flac` 的音量：比這個學員段落講話音量的
第 90 百分位低 20 dB 算安靜；逐字稿句子交界前後 0.3 秒內都算），切點在停頓正中間；8 秒以上遇到停頓就切，找不到就往後接、
最長 25 秒，還是沒有就切在句子之間最安靜的一點。同一段落裡相鄰兩格頭尾相接（`slot` 前一格的訖＝後一格的起）；段落頭尾、
刪除範圍兩邊照舊是句子起訖。`audio.flac` 不在時改用逐字稿的句子間隔判斷。切在沒有停頓的地方時，那一格多 `切在講話中`
（原片秒的清單：這一格頭或尾的切點），第 5 步要標出來。

內容檢查（0.2.1b1 起；老師、學員、保留原聲學員名字共用）：除了相似度 0.85，轉回文字漏掉連續 6 個字以上、
或要念的文字最後（最前）2 個字照順序在轉回文字的結尾（開頭）4 個字裡照讀音找不到（頭尾語助詞不算、有數字英文不判斷、
不到 6 個字的短句不判斷）也算沒念對，照原規則換種子重念。`嘗試[]` 每次多 `內容問題`（`漏了一串字`／`結尾可能少念了字`／
`開頭可能少念了字`，沒有就是 null）、`漏字數`（最長漏掉連續幾個字）；選定的那次還有問題時，這一句多 `內容問題`、`要人聽` 為真。
舊的 `_嘗試快取.json` 沿用時照新規則重新判斷（那一次不重新生成，沒過才換種子多念一次）。

「做過沒有」（0.2.1b1 起；老師、學員、保留原聲學員名字的紀錄都一樣）：紀錄對得上之外，`檔案`（選定檔）、`放回時間格.檔案`、`放回時間格.來源檔案` 都要在；有一個不在（清硬碟刪了、複製工作區沒帶到）就當作沒做過、再生成一次，`_嘗試快取.json` 裡聲音檔還在、指紋對得上的那幾次照樣沿用。

`生成/學員聲線.json`（09-30 改版）：`{版本: 2, 學員: {鍵: {檔案, 名稱, 性別, 依據, 人選的}}}`。鍵是本名（還沒選本名的用「學員N」），
合併／拆開學員後照本名沿用、不會配錯。每位學員一個聲線檔：男生依序用 `聲線/候選_0928/` 的男 1、男 2⋯，女生用女 1、女 2⋯（女 5 不用），
同一集每位不同（用完了才重複，記在依據）；第 3 步「學員是誰」可以改（`人選的: true`），選空白回到自動配。
性別：名冊（用本名找 `性別` 欄）→ 舊版判斷 → 原音估中位數基頻（低於 165 Hz 算男聲）。候選資料夾沒有某個性別時，用 `男聲_暫定`／`女聲_暫定` 當後備。
舊格式（`{學員N: {聲線: 男／女, 依據, 基頻Hz}}`）只拿來當性別參考。每段紀錄另外多 `聲線名稱`（男1、女3⋯）。

「文字欄就是模型拿到的稿子⋯⋯稿子對、轉回文字不對，才是模型念錯」。每一筆（依成品時間排序；0.2.0b1 起標題寫
「原片 0:42:59.8–⋯／成品 0:38:26.4–⋯」，時間到零點一秒，原片在前）：

| 欄位 | 內容 |
| --- | --- |
| 成品時間 | 刪除、停格之後的新時間（`render.to_output_time`） |
| 原片時間 | 原片的起訖 |

| 轉回文字 | Groq 把生成的聲音轉回的文字 |

`輸出/剪輯決策_<範圍>.json` 是同一份資料的機器版（`刪除`、`停格`、`模糊`、`動作`、`標記`、`片段`、`精準度`），
另外有：`範圍`、`警告`（給人看的一句話）、`警告明細[]`（`警告類型`、`id`、`類型`、`start`、`end`、`蓋過的`（別筆的 id）、`疊到的範圍`、`疊到秒`、`處理`；
`inspect 剪輯決策` 印這份）、`學員聲線`、`重疊沒處理[]`（重疊還留著原聲的：`id`、`start`、`end`、`做法`、`沒處理秒`）、`名字沒處理`（計畫裡沒被任何動作蓋到的名字）、`摘要`。

`併入前一格`（短於 0.05 秒的空隙，處理紀錄不另外列）、停格點錯開的 `停格錯開秒`／`停格錯開處理`／`開頭讓出秒`／`結尾多佔原片秒`；`停格[]` 多 `錯開秒`、`錯開處理`（10-04 #134，見下方處理紀錄）。
`輸出/輸出摘要_<範圍>.json` 記各輸出做法的耗時、大小、推估整支耗時、驗證結果（長度誤差、聲畫差、剪點黑畫面）。
10-20 總審查起另記 `老師名字計畫指紋`、`學員名字計畫指紋`：這次組裝用的名字處理計畫（老師那份讀 `生成/名字處理計畫.json`、保留原聲學員那份沒有存成檔）只看生成、消音的內容指紋（`nameplan.plan_key`，順序與時間戳不算）；第 4 步「組裝」做過沒有拿它跟現在排的比，不一樣就寫「名字的處理方式改了，要重新組裝（生成好的聲音沿用）」。舊摘要沒這兩欄：老師那份拿現在排的跟計畫檔整份比、學員那份拿 `剪輯決策_<範圍>.json` 實際處理的學員名字比。
另外記 `底噪挑法`（`roomtone.METHOD`）與 `組裝做法版本`（`render.ASSEMBLE_VERSION`，10-17 #122）：第 4 步「做過沒有」比對這兩欄，跟現在的程式不同就要重新組裝（生成好的聲音沿用）；舊摘要沒有 `組裝做法版本` 當第 1 版。

## `生成/處理紀錄.json`（proclog，09-29）

第 4 步每個動作一筆，第 5 步「成品檢查」的時間軸就是照這份畫的。`render video` 與 `render audio` 組完聲音都會重寫這份（留最後一次）。

**這份處理紀錄做出的是哪幾支成品**（10-13）：處理紀錄不另外記成品檔名。第 5 步用 `來源` 的範圍標記（`render video 0-98` 的 `0-98`）
找 `輸出/成品_<標記>_<做法>.mp4`（不含標字版、`_驗證沒過`），修改時間不早於 `產生時間` 減 2 秒的那幾支都算「這次做出的」
（兩種輸出方式都通過會有兩支，取最新的當預設；`finalcheck.log_products`）。0.2.2b1 第 3 段起檔名帶版本號 `成品_v<N>_<標記>_<做法>.mp4`：
處理紀錄多記 `版本號`（組裝前先預留，`needs.next_version_no`），有這一欄時只認那一版的檔名；比範圍標記時先去掉 `v<N>_`（`render.product_parts`）。
第 4 步「做過沒有」看同範圍、同做法版本號最大的那一支（`render.product_path`）。`來源` 是 `render audio`、或 `產生時間` 讀不懂時推不出來，第 5 步照以前的做法不切換。
推得出來但一支都沒找到（例如這次只做了標字版）時也不切換，但範圍標記跟這份處理紀錄不同的成品標「舊的」（不能輸出、不能判斷；10-13 審查修正），同標記的不標。

| `來源` | `render video <範圍>` 或 `render audio` |

**設定快照**（`handoff.build_snapshot`）：這一集的文字（紀錄檔裡的字串）當比對範圍——名冊留本名或其他寫法出現過的列（只留 `中文名, 其他寫法, 英文代號, 聲線, 性別` 欄）、
敏感詞留原詞出現過的、發音對照表留原字出現在這一集文字、英文代號或敏感詞替代詞裡的。UTF-8（加 BOM）。工作區已經有快照（匯入過）就照帶那一份，不從這台的設定重算。
有快照時讀快照的地方（`handoff.setting_path`）：`epcodes`（代號、照原聲名字）、`tts.pron_table_for`。最後一道隱私保險（`epcodes.replace_table` 的名冊列與敏感詞）用「快照＋本機」合起來（`handoff.setting_paths`，快照在前、同一個寫法留第一份），`students.roster_gender` 先查快照、沒有再查本機——快照只是讓第 4 步不因這台名冊不完整而變，不讓保險變弱。
發音對照表順序：老師句子且工作區自己有 `發音對照表.csv`（匯入覆核結果帶的）→ 設定快照 → 本機；學員句不看工作區自己那份（跟以前一樣）。沒有快照的舊工作區照舊。

**匯入**（`handoff.ImportJob`）：① 逐檔核對（少檔、大小或 SHA-256 不對、zip 讀不懂 →「交接包還沒下載完（或檔案壞了），請等雲端空間同步好再試。」）
→ ② 原片比對（大小一樣、長度差 1 秒內，不是就停）→ ③ 聲線比對（不同只提醒）→ ④ 匯入到哪一份（`handoff.find_target`，不靠原片放在哪）：專案清單上交出過 `上一棒交接編號` 那個包的工作區 → 同一個 `工作區ID`、而且不是交出這個包本身的那一份 → 都沒有才用原片旁邊的 `<檔名>_剪輯工作區/`（跟「選影片」同一套）；開始搬之前先看空間（要解開的大小＋1 GB，不夠就說要多少）：
這台沒有這一集＝建新（但第 5 步的包帶了上一棒、卻在專案清單找不到原本那一份時先問：另建一份，或打原本那一份的位置）；1、2 符合的不只一份＝列出來讓人選。人選了某一份或打了位置之後，不會直接換：先確認那一份的工作區 ID 跟包一樣（不一樣就停，「這不是同一集的工作區」），再照常比對一次（交接後又改過、比較舊、已經匯入過照樣問），比完才換。已有（有 `分析結果.json`）＝跟比對基準（見下方〈比對基準〉）比，有要問的就停在「要確認」：一句粗體重點＋一行說明＋改過的地方的白話分類（最多 3 類，不列檔名）＋「要換掉的工作區：資料夾名稱」；第 3 步的包在交出它的同一台匯入＝停（「這是這台自己交出去的交接包」）；第 5 步的包選的原片旁邊就是交出這個包的那一份＝停（「這個交接包是這台交出去的，不用在這台匯入。」）；其他要問的，
按「繼續匯入」才做；已結案的不收 → 解到 `.交接匯入中/`（邊解邊核對）→（已有）這台的紀錄（同 `record_files`）搬到 `備份/交接前_<日期時間>/`、`web快取/` 整個丟掉 →
包裡的檔換上（每個要放的位置照實際路徑要在工作區裡，中間資料夾是捷徑指到外面就停；包裡要放的位置原本有檔的也先備份；出錯時包裡搬進來的全部拿掉、備份搬回原位，這次新建的資料夾整個拿掉）→ `分析結果.json` 的 `video`、`transcript/merged.json` 的 `source`、`參考音/挑選紀錄.json` 的 `video` 改成這台選的原片 →
`修改需求/歷史.jsonl` 記一條 `動作: 交接匯入`（`後`：電腦、哪一段、匯出時間、交接編號；沒升級過的工作區不記）→ 每個檔的修改時間照交接清單還原（歷史、格式兩個檔除外）→
交接紀錄記一筆匯入 → `audio.flac` 不在就從原片重抽（抽不出來只提醒）。工具接著登記進專案清單、切到這一集，第 3 步的包到第 4 步、第 5 步的包到第 5 步。

**`交接/交接紀錄.json`**：`工作區ID`、`交出[]`（`時間`、`哪一段`、`檔名`、`路徑`（存的 zip）、`位置顯示`、`大小`、`交接編號`、`核對: 通過`、`紀錄指紋`（`{相對路徑: 指紋}`，用寫進包裡的那一份內容算，不是打包完再重讀工作區））、

**比對基準**（三審）：「包裡上一棒那次交出」與「這台最近一次匯入（匯入時記下匯入後的判斷指紋）」比較晚的那一筆；同一個交接包再匯入只說「已經匯入過了」；比上次匯入的還舊說「這是比較舊的交接包」（建議不匯入）；第 3 步的包在交出它的同一台（專案清單上有同一個工作區 ID、交出過這一包）匯入＝停，說「這是這台自己交出去的交接包」。確認視窗只寫一句重點＋一行說明，改過的地方用白話分類（`handoff.change_kinds`，最多列 3 類），不列檔名。路徑比對（專案清單、原片旁邊、目前開著的這一集）一律用 `workdir.same_path`（Mac 不分大小寫）。

**清理**（33 號設計 §6）：
- 第 3 步交接打包成功後問「清掉（建議）」「先留著」（`handoff.copy_clean_plan`／`clean_copy`，`POST /api/handoff/clean-copy {清單指紋}`）：清 `closing.classify` 判「暫存」的
  （`audio.flac`、`web快取/`、`chunks/`、`名字候選/`、`重疊/` 的聲音片段），不清 `參考音/`、`備份/`；WSL 上 `分析結果.json` 記的原片在 `~/讀書會剪輯資料/影片/` 最上層、
  沒有別的還沒結案的專案在用 → 原片複本一起刪（跟結案清空間同一個判斷 `closing._video_copy_row`、刪前再比位置與大小）；Mac 上原片是原檔，不列。三道保險：有核對通過的交接包、清單指紋一樣、只刪認得的。
- 第 5 步交接打包成功＝「已交出去」：總覽那一列多「已交出去」與「清掉這集（大小）」（`POST /api/handoff/clean-episode {路徑}`，`handoff.clean_episode`）。
  只有「匯入第 3 步交接包建出來的」工作區才有（老師自己第 1 步建的、就算按過第 5 步交接打包也沒有）。確認視窗寫「請確認交接包已經上傳到雲端空間」（宇軒 10-20：不再看 zip 還在不在）。清之前再確認：已交出去、交出去之後人做的判斷沒再改過、工作區是真的資料夾（不是捷徑）而且名稱是 `…_剪輯工作區`、有分析結果、沒結案。
  過了就整個工作區刪掉、原片複本照上面的規則一起刪（Mac 不碰原片），從專案清單拿掉。
- `備份/交接前_*/` 在結案清空間時算「暫存」一起清（`備份/` 其他照留）。
