# 套件版本鎖定（開發者用）

10-17 起（待辦 #241）`install.sh` 照 `requirements.lock` 裝套件，每個套件、連帶進來的相依都是確切版本。
起因：10-16 老師從頭安裝，`requirements.txt` 沒寫版本的 pyarrow 裝到 26.0.0（要 NumPy 2），工具固定 NumPy 1.26.4，第 4 步一載入 CosyVoice 就失敗。

## 三份檔案的分工

| 檔案 | 寫什麼 | 誰改 |
|---|---|---|
| `requirements.txt` | 直接用到的套件（大多有版本） | 開發者手改 |
| `constraints.txt` | Intel Mac 裝得到的版本上限 | 開發者手改 |
| `requirements.lock` | 上面兩份算出來的完整清單＋確切版本 | **不要手改**，跑 `bash update-lock.sh` 產生 |

`build-constraints.txt`（openai-whisper 建置用的 setuptools 上限）跟鎖定檔無關，install.sh 照舊帶入。

## 什麼時候要重產

改了 `requirements.txt` 或 `constraints.txt` 之後：

```bash
bash update-lock.sh            # 原本鎖的版本當偏好，沒必要變的不變
bash update-lock.sh --upgrade  # 要整批升級時才用
```

跑完把 `requirements.lock` 一起 commit。`tests/test_lockfile.py` 會檢查 requirements.txt 的每個套件都在鎖定檔裡。
鎖定檔有變的版本，更新說明要寫「這版要重跑 install.sh」。

## 產生方式

`uv pip compile requirements.txt -c constraints.txt --universal --python-version 3.11 --exclude-newer 2026-10-16T14:00:00Z`（指令全文見 `update-lock.sh`）。

- `--universal`：Mac（Apple Silicon／Intel）與 Linux（WSL2）共用一份，只在某些環境裝的套件行尾寫「; 條件」
- `--exclude-newer`：只用這個時間以前發布的版本（10-17 定：鎖成 10-16 晚全新安裝會裝到的版本，pyarrow 例外固定 25.0.1，寫在 requirements.txt）。新增套件需要更新的版本時才往後調
- 不列 `nvidia-*`、`triton`：只有 CUDA 版 torch 才要。沒有 NVIDIA 顯示卡的 Linux，install.sh 先從 PyTorch 的 CPU 專用來源裝 `torch==2.2.2+cpu`，鎖定檔的 `torch==2.2.2` 視為已滿足、不會換掉；有 NVIDIA 顯示卡的 Linux 照 PyPI 的 torch 自己帶 nvidia 套件
- 不列 `qwen-asr`、`bookclub`：install.sh 另外用 `--no-deps` 裝。install.sh 用 `uv pip install`（不是 `uv pip sync`），鎖定檔沒列的套件不會被移掉

## 健檢

`bookclub doctor` 的「套件版本跟鎖定檔一致」列出已裝版本跟鎖定檔不一樣的套件（只提醒，不算必要項目），修法是重跑 install.sh。
