## 畫面處理（學員的臉、Zoom 的姓名標籤）

這一版**只處理聲音與說出口的名字，不處理畫面**：學員的臉、Zoom 畫面上的姓名標籤都還在成品裡。
`render video` 的模糊只是固定位置的示範，正式成品（第 4 步「開始執行」）不加。

現在先這樣：成品要公開前，畫面請另外用剪輯軟體處理，或只用在不需要遮臉、遮姓名標籤的場合。

## Windows 的啟動捷徑

Mac 可以雙擊「啟動.command」開網頁；Windows（WSL2）還沒有對應的捷徑。

現在先這樣：照 README「怎麼用」在 Ubuntu 的終端機打 `bookclub serve`，再用 Windows 的瀏覽器開網址。

## 檔案進出：要在 Windows 實機驗證的（10-07 起）

10-07 的「選影片用系統選檔視窗、Windows 的檔自動複製進 Ubuntu、成品拿出來」只在 Mac 上模擬測過。在老師或夥伴的 Windows＋WSL2 上，照下面一項一項試，結果寫回這裡：

- 選檔視窗：按「選影片」會不會跳出來、會不會躲在瀏覽器後面；從按下到視窗出現要幾秒（用手機碼錶量，第一次與第二次各量一次：第一次 PowerShell 冷啟動通常比較久）；按鈕有沒有馬上變成「正在打開選檔視窗…」；選檔視窗開著時重新整理網頁或再按一次（預期第二次說「選檔視窗已經開著了」）。
- 路徑：Windows 使用者名稱是中文；路徑含空白、單引號、逗號、中文；D 槽（`/mnt/d/…`）；網路磁碟（`\\server\share\…`，預期轉不過來就退回網頁瀏覽）；選到 `\\wsl.localhost\Ubuntu\home\…` 裡的檔（預期直接用、不複製）。
- 空間：C 槽空間很少、但 Ubuntu 裡 `df -h ~` 顯示很多時，複製前會不會擋下來（工具同時看 `/mnt/c`）；Ubuntu 被搬到別的磁碟過的電腦，這個判斷準不準。
- OneDrive：影片放在 OneDrive 同步的資料夾（檔案可能只在雲端、還沒下載）；「下載」資料夾被 OneDrive 接管時，複製成品過去的行為。
- 複製中關掉伺服器：Ubuntu 這邊下次啟動是否清掉暫存檔；Windows 下載資料夾那邊留下的 `.….複製中` 要自己刪。
- 終端機：選完檔、複製成品後，開著伺服器的那個 Ubuntu 終端機有沒有變怪（打字不顯示、換行亂掉）；有的話跑 `reset`，並回報。
- 檔案總管：「在檔案總管打開成品資料夾」有沒有開在對的位置。
- Mac：用「啟動.command」開時，選檔視窗會不會跳到後面、會不會要求「自動化」或「輔助使用」的權限。

## 防睡眠：要在 Windows 實機驗證的（10-07 起）

10-07 起第 1、4 步跑的時候，工具會從 WSL2 叫起 Windows 的 `powershell.exe`，請 Windows 不要閒置睡眠（`bookclub/keepawake.py`，跟 Mac 的 caffeinate 同一類做法）。**只在 Mac 上用假的 powershell 測過**。研究報告：宇軒 repo 的 `reference/正念心教育/讀書會剪輯/28-研究-1007-Windows自動防睡眠.md`。

給老師或夥伴的 Claude 代跑：在 WSL2 的 Ubuntu 終端機、bookclub-edit 資料夾裡跑（寫「Windows」的除外），不需要影片、不碰工作區；結果寫回這裡。第 11 項要 Ubuntu 的系統管理員權限，請人自己打密碼。

1. **interop 開著**：`cat /proc/sys/fs/binfmt_misc/WSLInterop; ls /proc/sys/fs/binfmt_misc/`
   預期第一行 `enabled`。記下檔名是 `WSLInterop` 還是 `WSLInterop-late`（工具兩個都看）。
2. **找得到 PowerShell**：`which powershell.exe; ls -l /mnt/c/Windows/System32/WindowsPowerShell/v1.0/powershell.exe`
   預期至少一個有路徑。
3. **是不是 Modern Standby**：`powercfg.exe /a`
   有「待命 (S0 低電源閒置)」＝Modern Standby；「待命 (S3)」＝傳統睡眠。記下來。
4. **擋得住閒置睡眠嗎（最重要）**：
   `.venv/bin/python -c "import time; from bookclub import keepawake as k; off = k.keep_awake(print, on_status=print); time.sleep(7200); off()"`
   預期幾秒內印出「已請電腦不要睡⋯」。另開一個 Ubuntu 視窗打 `powercfg.exe /requests`，預期 `SYSTEM:` 底下有 `[PROCESS] ...powershell.exe`。
   同時跑 `while true; do date >> ~/awake_test.log; sleep 60; done`。**插電、不碰電腦** 30 分鐘以上（超過睡眠時間，讓螢幕自己關、自己鎖定）。
5. **承上，回來檢查**：`cat ~/awake_test.log`；Windows「事件檢視器」→ Windows 記錄 → 系統，篩來源 Kernel-Power。
   預期每分鐘都有一行、沒有斷層，期間沒有睡眠事件。**若螢幕關掉、鎖定之後還是睡著**：網頁那行要改說法，README 手動設定改成主要做法。
6. **結束後恢復**：在第 4 項那個視窗按 Ctrl+C，再打 `powercfg.exe /requests`。
   預期 `SYSTEM:` 底下是 `None`；之後閒置照原本設定會睡。
7. **WSL 這邊被砍，Windows 那支會不會跟著走**：重跑第 4 項的指令，另開視窗 `pkill -9 -f keepawake`；等 6 分鐘後打 `powercfg.exe /requests` 與 `tasklist.exe | grep -i powershell`。
   預期立刻（收到 EOF）或 5 分鐘內（沒有心跳）消失。記下是哪一種。
8. **用電池**：拔電源重做第 4 項。
   預期第 4 項的指令印出「偵測到現在用電池」；超過睡眠時間約 5 分鐘後還是會睡（Windows 的規定）。
9. **闔蓋**：插電，闔上螢幕 5 分鐘再打開，看 log 有沒有斷層。
   預期照「蓋上螢幕時」的設定睡著（程式擋不住，README 已寫）。
10. **闔蓋設定讀得到**（之後想加闔蓋提醒才需要）：`powercfg.exe /q SCHEME_CURRENT SUB_BUTTONS LIDACTION`
    預期看得到「AC 電源設定索引」；0＝不執行任何動作、1＝睡眠。
11. **interop 關掉時安靜退回**（請人自己打）：`sudo sh -c 'echo 0 > /proc/sys/fs/binfmt_misc/WSLInterop'`，啟動工具按第 1 或第 4 步；結束後 `sudo sh -c 'echo 1 > /proc/sys/fs/binfmt_misc/WSLInterop'`（或關掉 Ubuntu 重開）。
    預期工具照跑，網頁「防睡眠」那行與終端機都出現「沒辦法自動防止電腦睡眠（WSL2 叫不了 Windows 的程式…）」。
12. **防毒軟體（Defender／AMSI）會不會攔截或跳警告**：`-EncodedCommand`＋`Add-Type` 呼叫 kernel32 的寫法常被防毒盯上。第 4 項跑的時候看「Windows 安全性」→「保護歷程記錄」有沒有攔截或警告（有裝其他防毒也看一下）。
    預期沒有攔截；**若被擋**，工具應該走「沒開成」（終端機與網頁出現「沒辦法自動防止電腦睡眠（PowerShell 回報…／沒有回應）」）、照常跑完，並記下防毒顯示的名稱。
13. **終端機視窗**：第 4 項跑的時候，Ubuntu 的終端機視窗有沒有被藏起來、多跳出一個視窗、或之後打字變怪。預期都沒有。
14. **網頁實際跑一次**：第 1 步按「開始分析」，畫面上固定有一行「防睡眠：已請電腦不要睡⋯」；跑完那行消失。

第 4–7 項決定這個功能留不留；第 5 項若在「螢幕關掉＋鎖定」後還是睡著，就改成「工具＋README 手動設定」並在網頁講清楚。

## 片頭、片尾

選片頭、片尾的程式已經做好（各一支、可以不選，記在工作區的 `工作區設定.json`；WSL2 選到 Windows 的檔一樣先複製進 Ubuntu），**畫面先不顯示**：10-08 開發者決定片頭片尾要在第 5 步「輸出成品」那一區選（不放總覽），接著決定先把片頭片尾的選取功能隱藏起來。要打開：`bookclub/web/fileio.js` 的 `SHOW_EXTRAS` 改成 `true`，第 5 步輸出成品按鈕下方就會出現「片頭」「片尾」兩列（可以換、可以拿掉）。**成品還不會接上**，要先跟老師核對。每次「輸出成品」會把當時選的片頭片尾檔名記在 `覆核/成品檢查.json` 的 `輸出紀錄`（`接上片頭片尾: false`），接上之後可以對照。

接上要動到的地方（10-07 讀過 `bookclub/render.py`、`assemble.py`、`finalcheck.py` 的評估）：

- 做法一：第 4 步組裝時接上。成品時間會整體往後移片頭的長度：處理紀錄的 `片段`（第 5 步每一處成品時間的來源）、`to_output_time`／`from_output_time`、`timemap`、停格位置、看過的區段、處理標記清單、標字版、成品驗證的預期長度與剪點都要一起偏移；三種輸出做法（整段硬體、整段軟體、只重做片段）接法不同，`smart` 在 Mac 用 AVFoundation 接，片頭片尾要先轉成跟主片一樣的解析度、幀率、聲音取樣率與編碼參數才接得上。估約 1.5～2 天（含測試），風險在第 5 步的時間換算。
- 做法二（建議）：第 5 步按「輸出成品」時才接。檢查用的成品不變，時間換算都不用動；只在複製成 `最終成品_…` 那一刻，把片頭、片尾用 ffmpeg 轉成跟主片一致（解析度、幀率、48kHz 聲音）再接起來（整支重新編碼一次，98 分鐘的片約十幾分鐘，要背景跑、顯示進度）。估約半天到 1 天。

現在先這樣：成品輸出後，用剪輯軟體自己接上。

## 第 1 步的轉文字

- 轉文字每次都可能隨機漏掉幾段（有人講話，但逐字稿沒有字）。現在第 4 步開始前總檢查會列出「有人聲但沒有字」，要人聽過；還沒有自動補轉。
- 沒人講話的地方，轉文字偶爾會自己冒出字。現在只在終端機印統計（`bookclub inspect <工作區> 字` 也看得到），不會自動刪。
- 段落有時切得比較碎（同一個人連續講，被切成好幾段）。現在先在第 3 步用「併進上一段」合併。

## 第 1 步找重疊比較慢、沒有用到顯示卡

找重疊是第 1 步最花時間的一段，目前 Mac 與 Windows 都只用處理器在算。

現在先這樣：第 1 步可以放著跑，人離開沒關係。

## 名字

- 名字整句換掉時，重念的範圍照「一句」的起訖，不會往前後延伸到停頓處（程式做好了，還沒打開）。
- 有時會多出幾張要人看的名字卡（不會漏，只是多看幾張）。
- 名字卡上還沒顯示這筆候選是從哪一類句子找到的；要知道的話用 `bookclub inspect <工作區> 名字` 查。

## 學員重念

- 少念 1–3 個字的句子，目前照樣算通過（少念 6 個字以上、或頭尾的字沒念到才會擋下來）。第 5 步請用耳朵聽。
- 學員講很長、被切成很多格的地方，有些格子會念得比原本快一點；第 5 步標紅的格子請聽一下，不對就退回。

## 第 5 步的退回原因交給 AI 參考

第 5 步退回時寫的原因，現在還不會交給 AI 參考（例如念錯字 → 改發音對照表；停頓不自然 → 不插入停頓）。文字和範圍都沒改的退回，只會換一種念法重新生成，不看原因。之後跟「把第 3～5 步的決定與退回原因都記下來」一起做。

## 霧化（消音的另一種方式）

`覆核決定.json` 的消音 `方式` 可以選「霧化」，但組裝時還是墊底噪（處理紀錄註明「霧化還沒做，先墊底噪」）。
要做的：用濾波器讓人聲變得霧霧的，聽得出處理過、不影響理解；**用在名字或敏感內容時要確認聽不出字**——霧化後丟 Groq 轉文字，
轉得出名字就不合格，退回墊底噪並列在報告裡。

## 影片的畫面格數

組裝時畫面格數照每秒 25 格處理，還沒有自動偵測影片本身的格數。Zoom 錄影多半是每秒 25 格；不是的影片會怎樣還沒測過。

## 移植到 Windows 要注意

| 地方 | Mac 現在 | Windows 要怎麼辦 |
| --- | --- | --- |
| 輸出做法 | 預設整段軟體編碼（libx264） | 一樣，結果相同 ✓ |
| 硬體編碼 `hw` | `h264_videotoolbox`（Mac 才有） | 要看顯示卡：NVIDIA `h264_nvenc`、Intel `h264_qsv`、AMD `h264_amf`，各自實測；沒有就不能用 |
| 只重做片段 `smart` | 用 AVFoundation 接片段（`bookclub/avconcat.swift`，Mac 才有） | 退回 ffmpeg 接：QuickTime 確定解不了，Windows 的播放器、剪輯軟體要實測 |
| QuickTime 相容檢查 | `avconvert` | 沒有這個指令，自動跳過（驗證結果記 `null`） |
| Groq 金鑰 | 放 `~/.zshrc`，要用 `zsh -ic` 啟動 | WSL2 放 `~/.profile`（不要放 `~/.bashrc`：Ubuntu 的 `.bashrc` 在非互動模式會提早結束，工具讀不到；跟 README、`doctor` 一致）；原生 Windows 用系統環境變數 |
| 防睡眠 | 第 1、4 步執行時工具自己用 `caffeinate` 防止閒置睡眠 | 10-07 起工具從 WSL2 叫 Windows 的 PowerShell 擋閒置睡眠（`bookclub/keepawake.py`，還沒實機驗過，見「防睡眠：要在 Windows 實機驗證的」）；闔蓋、電池、Windows 更新仍要人處理（README「Windows：跑之前先把電腦設成不睡眠」） |
| 路徑 | 中文路徑沒問題 | ffmpeg、Python 都要實測中文路徑。10-07 起網頁「選影片」選到 Windows 磁碟（`/mnt/c/…`）的檔案會自動複製進 `~/讀書會剪輯資料/影片/`，工作區不會建在 Windows 磁碟上；選檔視窗（PowerShell 的 OpenFileDialog）回傳中文、空白路徑再用 `wslpath` 轉，只在 Mac 上模擬測過 |
| 選檔視窗 | `osascript -l JavaScript` 的 chooseFile（10-08 起；AppleScript 版的 `activate` 每次多等約 2.2 秒） | WSL2 透過 interop 叫 `powershell.exe -STA` 開 OpenFileDialog；interop 關掉（`/etc/wsl.conf` 的 `[interop] enabled=false`）或找不到 `powershell.exe` 時退回網頁資料夾瀏覽。還沒在 Windows 實機試過 |
| 字型 | 標字版用 STHeiti | Windows 用微軟正黑體（`msjh.ttc`），`render.FONT_CANDIDATES` 要加；只影響標字試看版 |
| 環境健檢 | `bookclub doctor` | WSL2 還少幾項檢查 |
